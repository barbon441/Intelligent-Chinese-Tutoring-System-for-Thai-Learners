# ระบบติวเตอร์ภาษาจีนอัจฉริยะสำหรับคนไทย (จีนรู้ใจ) — สรุปโปรเจกต์ + แนวทาง + โครงร่างโครงงาน
> Intelligent Chinese Tutoring System for Thai Learners

> **ไฟล์นี้คืออะไร:** เอกสารสรุปฉบับสมบูรณ์ของโปรเจกต์จบ "จีนรู้ใจ" สำหรับนำไปทำงานต่อในเครื่อง/เครื่องมือ AI อื่น — รวมทั้งรายละเอียดเชิงเทคนิค แนวทาง ข้อควรระวัง และโครงร่างโครงงาน (1.1–1.9)
> **ทีม:** 2 คน — เพื่อน (เชี่ยวชาญภาษาจีน = เนื้อหา/การสอน) + บอล (วิศวกร + ผู้เรียนจีนมือใหม่ = ผู้ใช้ทดสอบจริงคนแรก)
> **สาขา:** วิทยาการคอมพิวเตอร์ มหาวิทยาลัยแม่โจ้ · **เวลา:** ~4 เดือน (ก.ค.–ต.ค. 2569) · **งบ:** ฟรี/ต่ำสุด
> **สถานะ:** ขั้นออกแบบ ยังไม่เริ่มเขียนโค้ด · **อัปเดต:** 2026-06-28

## 0. TL;DR (สรุป 30 วินาที)

**จีนรู้ใจ = ติวเตอร์ภาษาจีนที่จำผู้เรียนได้ รู้ว่า "คนไทยคนนี้" อ่อนคำ/เสียง/ไวยากรณ์ตรงไหน แล้วปรับการสอน/ทบทวนให้เฉพาะบุคคล**

- **แก่นวิชาการ (ผลงานที่สร้างเอง):** แบบจำลองผู้เรียน (Learner Model) = ความแม่นรายทักษะ (Knowledge Tracing) + คลังวินิจฉัยจุดผิดเฉพาะคนไทย (Thai-L1) + จัดตารางทบทวน (Spaced Repetition)
- **จุดต่างหลัก:** Thai-L1 — ไม่มีแอปไหนสอนแบบรู้จุดผิดเฉพาะคนไทย
- **ทำได้ฟรี:** ใช้ของสำเร็จรูปเป็นวัตถุดิบ (py-fsrs, pyBKT, jieba, pypinyin, edge-tts, LLM) แต่ "จานเด็ด" (Thai-L1 model) สร้างเอง
- **วัดผลได้:** AUC + อัตราการจดจำเทียบ baseline + ablation → ทำให้เป็น "งานวิจัย" ไม่ใช่ "แค่แอป"

## 2. ปัญหา & แรงจูงใจ (ข้อมูลตรวจสอบแล้ว)

- ภาษาจีนเป็นภาษาต่างประเทศอันดับ 2 ของไทย ผู้เรียน HSK เยอะและโตต่อเนื่อง
- แอปในตลาดส่วนใหญ่เน้น "ท่องจำ" (recognition) ซ้ำซาก น่าเบื่อ ไม่ฝึก "ใช้จริง" (production)
- แอประดับโลกสอน "ทุกชาติเหมือนกัน" ไม่สนภาษาแม่ → ทั้งที่ภาษาแม่กำหนดรูปแบบความผิด (L1 transfer)
- **คนไทยมีจุดอ่อนเฉพาะ:** ฟังวรรณยุกต์ออก แต่ **ออกเสียงผิด** (เอาเสียงไทยมาแทน), เสียงม้วนลิ้น zh/ch/sh, ไวยากรณ์ถ่ายโอนจากไทย → ไม่มีแอปไหนแก้เฉพาะจุดนี้
- "จำผู้เรียนได้" เป็นเรื่องธรรมดาแล้ว (Duolingo, Praktika ฯลฯ) + แอปจีนสำหรับคนไทยก็มี (Chinesia, TangTang, MigiiHSK) → **ช่องว่างจริง = Thai-L1 pedagogy + closed loop (จับอ่อน→สอนซ้ำ→เทสต์จนแม่น)**

## 7. การตัดสินใจเชิงเทคนิค & เหตุผล

1. **FSRS ≠ mastery!** FSRS = จัดเวลาทบทวน (retention ต่อการ์ด) เท่านั้น. ความแม่นรายทักษะต้องใช้ **pyBKT** แยกต่างหาก. โครงแก่น = **pyBKT (วัดแม่น) + FSRS (จัดเวลา) + Thai-L1 (วินิจฉัย)**
2. **คนไทยฟังวรรณยุกต์ออกอยู่แล้ว (~91%) → ปัญหาจริงคือ "ออกเสียง" (production)** ไม่ใช่ "ฟัง" (perception). ดังนั้นเน้น production + ไวยากรณ์; ดริลฟังทายเสียงมีคุณค่าน้อยสำหรับคนไทย. เลี่ยง ASR ด้วยการโชว์ pitch contour
3. **สร้าง learner model เอง อย่าใช้ agent สำเร็จรูปเป็นแกน** — ต้องโปร่งใส วัดได้ (กรรมการต้องเห็นว่าเป็นผลงานเรา). LLM = ผู้ช่วย stateless เท่านั้น ห้ามให้ LLM "เป็น" learner model
4. **MCP = stretch/demo** (local stdio = wow-per-hour สูง; remote หลายคน = ติด OAuth = scope creep ข้าม)
5. **Hermes Agent / Mem0 / Letta = cite/แรงบันดาลใจเท่านั้น** — Hermes ไม่รองรับ LINE, "self-improving" = จำ text ไม่ใช่ knowledge tracing; agent-memory เก็บข้อความ ไม่ใช่คะแนนที่วัดได้
6. **Deep KT (DKT/AKT) = future work** — กินข้อมูลมหาศาล ผู้ใช้น้อยเทรนไม่ได้; ใช้ pyBKT (เบา โปร่งใส) ก่อน

## 9. ระเบียบวิธี: Learner Model + Thai-L1 Diagnosis (รายละเอียดเชิงเทคนิค)

### 9.1 Mastery Model (ประเมินความแม่น)
- หน่วยที่ติดตาม: ระดับคำ + ระดับทักษะย่อย (เสียงวรรณยุกต์ 1-4/เบา, พยัญชนะ zh/ch/sh/ฯลฯ, ส่วนประกอบอักษร)
- state ต่อหน่วย: เห็น/ถูก/ผิดกี่ครั้ง, ความแม่นล่าสุด, เวลาตอบ, สถานะ FSRS, เห็นล่าสุดเมื่อไหร่
- คำนวณความแม่น: ใช้ **pyBKT** → ค่าความน่าจะเป็นที่ผู้เรียน "รู้" ทักษะนั้น (โปร่งใส อธิบายได้)
- **Q-matrix:** ตารางเชื่อม "คำ → ทักษะที่ใช้" → ตอบผิดอัปเดตความแม่นของทักษะที่เกี่ยว ไม่ใช่แค่คำ

### 9.2 Thai-L1 Diagnosis (วินิจฉัยจุดผิดคนไทย)
- **คลัง error คนไทย (สร้างเอง):** entry = {id, คำอธิบาย, วิธีตรวจจับ, วิธีสอนซ้ำ, แหล่งอ้างอิง} — เช่น tone_2_3_confusion, retroflex zh→j, ไวยากรณ์ลำดับคำ/ลักษณนาม
  - แหล่งวัตถุดิบ: งานวิจัยภาษาศาสตร์ + ความรู้เพื่อน + ข้อมูลบอล + ข้อมูลจากแอปเอง
- **categorizer:** เอา (คำตอบถูก, สิ่งที่ตอบ) มาแยกด้วย pypinyin → ติดป้ายหมวดความผิด
- **aggregator:** นับ error ตามหมวด → เกินเกณฑ์ → ยกธงจุดอ่อน → เทียบคลัง Thai-L1
- **remediation (closed loop):** เจอ pattern → อธิบาย (ไทย) + ดริล minimal pair + แทรกคำกลุ่มนั้นเพิ่ม + FSRS เอากลับมาเร็วขึ้น

### 9.3 ระดับการทำ
- เริ่ม: rule-based + นับ + pyBKT (ทำได้จริง ข้อมูลน้อยก็ได้)
- future: Cognitive Diagnosis เต็มรูป / Deep KT / LLM ช่วยวินิจฉัย

## 10. การวัดผล (Evaluation) — ห้ามตัด! (= ตัวแยก A กับ B)

- **ตัวชี้วัด:** AUC/accuracy ของการทำนายว่าผู้เรียนจะตอบทักษะถัดไปถูกไหม (มาตรฐาน KT) + อัตราการจดจำ (retention) + เวลาตอบ
- **เทียบ baseline:** ตารางทบทวนของเรา vs ตารางคงที่ / Leitner / SM-2
- **Ablation:** มี/ไม่มี Thai-L1 diagnosis, มี/ไม่มี personalization
- **ผู้เข้าร่วม:** ⚠️ n=1 (บอล) ไม่พอ → ใช้ public dataset (เช่น Duolingo SLAM) สำหรับ validate model + เก็บผู้ใช้จริง 5-15 คน (เพื่อน/รุ่นน้องที่เรียนจีน) + บอล = case study เชิงลึก
- เก็บ log ทุก interaction ตั้งแต่วันแรก = นี่คือ dataset

## 13. โครงร่างโครงงาน (1.1–1.9)

**ชื่อ (ไทย):** ระบบติวเตอร์ภาษาจีนอัจฉริยะสำหรับคนไทย (จีนรู้ใจ)
**ชื่อ (อังกฤษ):** Intelligent Chinese Tutoring System for Thai Learners
**ผู้จัดทำ:** [ชื่อ-รหัส x2] · **อาจารย์ที่ปรึกษา:** [อาจารย์]

### 1.1 ที่มาและความสำคัญของปัญหา
ภาษาจีนเป็นภาษาต่างประเทศที่สำคัญลำดับต้นของไทย ผู้เรียนและผู้สอบ HSK เพิ่มต่อเนื่อง แต่แอปในตลาดเน้นท่องจำซ้ำซาก ไม่ฝึกการใช้จริง และสอนทุกชาติเหมือนกันโดยไม่คำนึงภาษาแม่ ทั้งที่ภาษาแม่กำหนดรูปแบบความผิด (L1 transfer) ผู้เรียนชาวไทยมีจุดอ่อนเฉพาะ (ออกเสียงวรรณยุกต์ผิด, เสียงม้วนลิ้น, ไวยากรณ์ถ่ายโอน) ที่แทบไม่มีแอปใดวิเคราะห์อย่างเป็นระบบ จึงพัฒนา "จีนรู้ใจ" ที่ใช้แบบจำลองผู้เรียน (Knowledge Tracing) + การทบทวนแบบเว้นช่วง (Spaced Repetition) + การวิเคราะห์เปรียบต่างไทย-จีน เพื่อเรียนรู้ตัวผู้เรียนและปรับการสอนเฉพาะบุคคล วัดผลได้เชิงวิทยาศาสตร์

### 1.2 วัตถุประสงค์
1) พัฒนาเว็บแอป (PWA) ติวเตอร์จีนสำหรับคนไทย ใช้งานออฟไลน์ได้ 2) พัฒนา learner model ประเมินความแม่นรายทักษะด้วย Knowledge Tracing 3) พัฒนาคลังวินิจฉัยจุดผิดเฉพาะคนไทย (วรรณยุกต์/เสียง/ไวยากรณ์) 4) ใช้ FSRS จัดทบทวนเฉพาะบุคคลให้ดีกว่าตารางคงที่ 5) พัฒนาฟีเจอร์ AI (LLM) ที่ทำงานร่วมกับ learner model — สร้างเนื้อหาเฉพาะบุคคล + คู่สนทนาที่ปรับตามจุดอ่อน 6) ประเมินผลเชิงทดลองว่าช่วยการเรียนรู้จริง (รวมเทียบ BKT vs Deep KT)

### 1.3 ฮาร์ดแวร์ ซอฟต์แวร์ เครื่องมือ และเทคโนโลยี
- **ฮาร์ดแวร์:** โน้ตบุ๊ก 2 เครื่อง, ไมโครโฟน/หูฟัง
- **ภาษา/DB:** Python, TypeScript, SQL (SQLite/PostgreSQL)
- **เฟรมเวิร์ก/ไลบรารี:** React/Next.js (PWA), FastAPI, py-fsrs, pyBKT, jieba, pypinyin, makemeahanzi, edge-tts/MeloTTS
- **AI:** LLM (Gemini/Typhoon) แบบ stateless
- **เครื่องมือ:** VS Code, Git/GitHub, Node/npm, ชุดข้อมูล HSK 3.0

### 1.4 วิธีการศึกษา
1) ศึกษาทฤษฎี/งานวิจัย (SRS, KT, contrastive analysis ไทย-จีน) 2) ศึกษาเครื่องมือ 3) รวบรวมคลังคำ HSK + จัดทำคลัง Thai-L1 4) ออกแบบ DB + สถาปัตยกรรม (engine แยก) 5) พัฒนา learner model (pyBKT + วินิจฉัย + FSRS) 6) พัฒนาเว็บแอป 7) ทดลองกับผู้เรียนจริง + เก็บข้อมูล 8) ประเมินผล (AUC/retention/ablation) + ปรับปรุง + เขียนรายงาน

### 1.5 ขอบเขตของโครงงาน
เว็บ/PWA สำหรับผู้เรียนไทย ระดับ HSK 1–2 (มาตรฐาน 3.0) ทีม 2 คน 4 เดือน. โมดูล: คลังคำ+บัตรคำ, learner model (mastery), Thai-L1 diagnosis, FSRS, แต่งประโยค+ฟีดแบ็ก, AI สร้างเนื้อหาเฉพาะคุณ, AI คู่สนทนารู้จุดอ่อน, วิเคราะห์เสียง (pitch contour), dashboard, ออฟไลน์. **นอกขอบเขต (future):** สแกนอักษรจีนจากกล้อง (multimodal OCR), ASR pronunciation scoring เต็มรูป, Deep KT เป็นโมเดลหลัก (ทำแค่เทียบบน public dataset ในช่วงวัดผล), MCP remote, ผู้ช่วยทั่วไป. **คำจำกัดความ:** Learner Model, Knowledge Tracing, Mastery, Spaced Repetition/FSRS, Thai-L1/L1 transfer, HSK, Q-matrix, Production vs Recognition

### 1.6 ประโยชน์ที่คาดว่าจะได้รับ (มุมวิทยาการคอมพิวเตอร์)
1) ได้สถาปัตยกรรม+ต้นแบบ Learner Model แบบ frontend-agnostic ใช้ซ้ำได้ (วิศวกรรมซอฟต์แวร์/ออกแบบระบบ) 2) ได้วิธีประยุกต์ Knowledge Tracing + FSRS กับการเรียนจีนของผู้เรียนไทย (ผลงานวิจัยอ้างอิงได้) 3) ได้ทรัพยากรเชิงคำนวณใหม่ = Thai-L1 Error Catalog + Q-matrix (ชุดข้อมูลที่ผู้อื่นต่อยอดได้) 4) ได้ผลประเมินอัลกอริทึมเชิงปริมาณ (AUC, retention vs baseline, ablation) = พิสูจน์เชิงประจักษ์ 5) ได้แสดงการบูรณาการ NLP + ML/learner model + PWA + DB/system design 6) ได้ฐานต่อยอดเชิงวิชาการ (Deep KT, การประเมินเสียง, ภาษาอื่น, MCP)

## 14. การตอบเรื่อง "ทำไมของเราดีกว่าแอปอื่น" (เตรียม defense)

- **อย่าเคลม "ดีกว่า Duolingo"** (ชนะไม่ได้). พูดว่า "เจาะจุดที่แอปใหญ่ทำแบบทั่วไป/ไม่ทำ"
- จุดต่างที่ป้องได้: (1) **Thai-L1** สอนแบบรู้จุดผิดเฉพาะคนไทย (มีงานวิจัยรองรับ) (2) วินิจฉัยสาเหตุ+สอนซ้ำ ไม่ใช่โชว์ข้อเดิม (3) ระดับ "รูปแบบความผิด" ไม่ใช่แค่ "คำ" (4) ออฟไลน์
- ยอมรับว่ามีคู่แข่งแล้วเฉือนช่องตัวเอง = น่าเชื่อถือกว่าเคลมว่าไม่มีใครเหมือน

## 15. 📌 หมายเหตุสำหรับ AI/ผู้ช่วยที่จะมาช่วยสร้างต่อ

- โปรเจกต์ยังไม่เริ่มโค้ด — เริ่มที่ MVP เดือน ก.ค.: คลังคำ + บัตรคำ + เสียง ก่อน
- โครงโค้ดแนะนำ: แยก `core/` (learner model — ไม่ผูก frontend), `api/` (FastAPI), `web/` (React PWA) — ทั้งหมด import `core/` ตัวเดียวกัน
- **อ่านข้อ 7 (การตัดสินใจ) + ข้อ 8 (ข้อควรระวัง) ให้ดี** โดยเฉพาะ: FSRS≠mastery (ใช้ pyBKT), เน้น production ไม่ใช่ perception, อย่าให้ agent กลืนแกน, อย่า scrape ข้อสอบจริง
- เป้าหมาย: ฟรีทั้งหมด, รองรับภาษาไทย, มี evaluation เชิงวิทยาศาสตร์ (ห้ามตัด)
- ผลงานหลัก = Thai-L1 learner model (สร้างเอง) ส่วน FSRS/NLP/LLM = เครื่องมือยืมมา
