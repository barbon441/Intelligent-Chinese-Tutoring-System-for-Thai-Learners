## 0. TL;DR (สรุปใน 30 วินาที)

**知音 (น้องยิน)** = ผู้ช่วย AI ส่วนบุคคลบน LINE สำหรับคนไทย ที่:
1. 🧠 **จำเราได้ + เรียนรู้ว่าเราเป็นคนแบบไหน** (ความจำคล้ายมนุษย์ + RAG + โปรไฟล์ผู้ใช้ที่เติบโต) ← หัวใจ
2. 📁 **เก็บไฟล์ไม่ให้หมดอายุ** (File Vault — แก้ปัญหาจริงของ LINE)
3. 📝 **สรุปแชต** ให้อัตโนมัติ + ตั้งเตือน
4. 🔌 เปิดความจำผ่าน **MCP** ให้ AI ตัวอื่น (Claude/ChatGPT) มาใช้ได้
5. 🔐 **โปร่งใส + ควบคุมได้** — ผู้ใช้ดูได้ว่าจำอะไร และสั่งลืมได้ (ความไว้ใจ = จุดขาย)

**แก่นวิชาการ** = Memory Engine (สกัดข้อเท็จจริง + ลืมแบบมนุษย์ + ค้นคืนแบบผสม + รองรับภาษาไทย + เรียนรู้ตัวตนผู้ใช้) ที่ **วัดผลด้วย benchmark + ablation study**

ทำได้ด้วยงบ **~0 บาท** (free tier ทั้งหมด) | ระยะเวลา **4 เดือน**

## 1. วิสัยทัศน์ (Vision)

ชื่อโครงงาน:
- **ชื่อผลิตภัณฑ์:** 知音 (Zhīyīn) / "น้องยิน"
- **ชื่อวิชาการ (ไทย):** ผู้ช่วยปัญญาประดิษฐ์ส่วนบุคคลบนแพลตฟอร์ม LINE ที่มีระบบความจำคล้ายมนุษย์และคลังเก็บไฟล์อัจฉริยะ
- **อังกฤษ:** LINE Personal AI Assistant with Human-like Memory and an Intelligent File Vault

แนวคิดสถาปัตยกรรมหลัก: **"สร้างสมองครั้งเดียว เปิดได้หลายช่องทาง" (Build the brain once, expose it many ways)**
- สมอง = Core Memory Engine (สร้างเอง = ส่วนที่ได้คะแนน/ความว้าว)
- ช่องทาง = LINE (ผู้ใช้ทั่วไป) + MCP server (ให้ AI อื่นใช้)

> 💡 **หัวใจที่ทำให้ไม่ใช่ "แค่เอา AI มาห่อ":** สมอง (LLM) เรายืม Claude/GPT มา — แต่สิ่งที่เราสร้างคือ *ทุกอย่างรอบ ๆ สมอง* = ความทรงจำ + การเรียนรู้ตัวตนผู้ใช้ + การอยู่ในไลน์ + ความไว้ใจ นี่คือแก่น CS ทั้งหมด

## 2. ชื่อ 知音 (น้องยิน) — ความหมาย

- **จีน:** 知音 = "ผู้ที่เข้าใจเราอย่างลึกซึ้งที่สุด" (จากเรื่องป๋อหยา–จงจื่อชี นักดนตรีกับคนเดียวที่ฟังเข้าใจเสียงในใจเขา)
- **ไทย:** "ยิน" = ได้ยิน → "ผู้ที่ได้ยินเสียงในใจคุณ และเข้าใจคุณ"
- **音 (จีน) = เสียง** → ชื่อนี้ทำงานได้ทั้งสองภาษา + คนไทยเรียก "น้องยิน" ง่าย

## 3. แรงบันดาลใจ (เรื่องเล่าสำหรับตอน defense — ไพ่เด็ด)

- มาจากความรักในอนิเมะ **Sword Art Online** — โดยเฉพาะ **คายาบะ อากิฮิโกะ** (ผู้สร้างโลกที่มี AI มีชีวิตอยู่ข้างใน) และ **Yui** (AI ที่รู้จักและผูกพันกับคนจริง ๆ)
- เป้าหมาย: สร้าง AI ที่พยายามเป็น "知音" ให้ผู้ใช้แต่ละคน — เหมือน JARVIS / Yui ที่มาอยู่ในไลน์ของเรา
- **เล่าเรื่องนี้ตอน defense** = กรรมการจะจำเราได้ เพราะโปรเจกต์มีหัวใจ ไม่ใช่แค่เทคนิค

## 4. ปัญหา & แรงจูงใจ (ตรวจสอบแล้ว)

- **LINE ครองตลาดไทย:** ~54-56 ล้านผู้ใช้ (~80% ประชากร) เป็นเครื่องมือทำงานหลัก โดยเฉพาะอาจารย์/คนทำงาน
- **ปัญหาไฟล์หมดอายุ (จริง):** LINE เก็บไฟล์/รูป/วิดีโอบนเซิร์ฟเวอร์ "ระยะเวลาจำกัดที่ไม่เปิดเผย" หลังจากนั้นเปิด/ดาวน์โหลดไม่ได้ (ตัวเลข "14 วัน" เป็นข่าวลือ ไม่ใช่ทางการ — **ห้ามอ้างเป็นข้อเท็จจริง**)
- **LINE Keep ถูกยกเลิก 28 ส.ค. 2024** → เกิดช่องว่างเรื่องที่เก็บไฟล์ถาวร (ช่องว่างจริง = "ที่เก็บถาวร + ค้นหาได้")
- **ปัญหาอื่น:** แชตล้น, หาข้อมูลเก่ายาก, ไม่มีระบบสรุป, ต้องตอบซ้ำ ๆ เอง
- **มีงานวิจัยรองรับ:** การใช้ LINE ทำงานส่งผลลบต่อ work engagement ของอาจารย์ไทย
- **ช่องว่างตลาด:** บอท LINE ในไทยเป็น B2B ตอบลูกค้าหมด (ZWIZ.AI, Botnoi ฯลฯ) — **ไม่มี "ผู้ช่วยส่วนบุคคล"**
- ⚠️ **ความเสี่ยง/ที่ต้องจับตา:** กระแส agentic AI มาแรงปี 2026 — แต่จากที่ตรวจสอบ AI ของ LINE เองตอนนี้เน้น "เพื่อธุรกิจ" (ตอบลูกค้า/ขายของ) + ฟีเจอร์เล่น ๆ (AI selfie) *ยังไม่ใช่ผู้ช่วยส่วนตัวที่จำเราได้* → ช่องว่างของเรายังเปิดอยู่ แต่ต้องตามข่าวไว้ และชูจุดต่าง (ส่วนตัว / privacy / File Vault / ภาษาไทย / **เรียนรู้ตัวตนผู้ใช้**)

### 🔍 เทียบกับของที่มีอยู่ (Related Work) — ใช้ตอบกรรมการ

ในตลาด LINE ไทยตอนนี้มีบอท/ผู้ช่วยหลายตัว แต่ทุกตัวเป็น "เพื่อธุรกิจ" / "ทำงานเดียว" / "คุยเล่น" — **ยังไม่มีใครทำ "AI ส่วนตัวที่จำเราและเรียนรู้ตัวตนเราในระยะยาว"**

| คู่แข่ง | ใครทำ / เพื่อใคร | งานหลัก | จำ + เรียนรู้ตัวตนเรา? |
|---|---|---|---|
| ขุนทอง | ธ.กสิกร (KBTG) / กลุ่มเพื่อน | หารบิล ทวงเงิน จ่ายเงิน | ❌ จงใจไม่เก็บบทสนทนา |
| ZWIZ.AI | สตาร์ทอัพไทย / ธุรกิจ-ร้านค้า | ปิดการขาย เก็บ lead ติดแท็กลูกค้า ตอบแชต | ❌ (จำ "ลูกค้า" เชิงขาย ไม่ใช่จำ "เรา") |
| Botnoi (บอทน้อย) | ดร.วินน์ / ธุรกิจ + คุย-เสียง | คุยไทยธรรมชาติ, เสียง AI (TTS), งานองค์กร | ❌ ไม่เรียนรู้ตัวตนระยะยาว |
| AI ของ LINE เอง | LINE / ธุรกิจ-ร้านค้า | ตอบลูกค้าอัตโนมัติ ติดแท็ก ขายของ + ของเล่น (AI selfie) | ❌ |
| **น้องยิน (知音)** | **เรา / คน ๆ หนึ่ง (ส่วนตัว)** | **จำเรา เรียนรู้ตัวตนเรา + File Vault + สรุป** | ✅ **คือหัวใจของทั้งโปรเจกต์** |

> **บทสรุปสำหรับ defense:** คู่แข่งทุกตัวเป็น B2B / ทำงานเดียว / คุยเล่น → ช่องว่าง = "ผู้ช่วยส่วนตัวที่จำและเรียนรู้ตัวตนผู้ใช้ระยะยาว + ภาษาไทย + วัดผลเชิงวิทยาศาสตร์" = น้องยิน
> หมายเหตุ: ฟีเจอร์ "แปลภาษาขณะคุย" ZWIZ ทำขายแล้ว → เป็นเหตุผลที่เราพักเรื่องล่ามไว้เป็น "ของแถม" (ดูข้อ 6)

**แล้วทำไมไม่ใช้ GPT/Claude เปล่า ๆ ไปเลย?** (คำถามที่กรรมการถามแน่)

| | GPT / Claude เปล่า ๆ | น้องยิน |
|---|---|---|
| ความทรงจำ | เปิดแชตใหม่ = ลืมหมด | **จำเราได้ตลอด สะสมทุกวัน** |
| รู้จักเรา | ไม่รู้ว่าเราเป็นใคร | **เรียนรู้นิสัย/ของที่ชอบเรา** |
| อยู่ที่ไหน | ต้องเปิดแอป/เว็บเอง | **อยู่ในไลน์ที่ใช้ทุกวัน** |
| ทักก่อนได้ไหม | ไม่ได้ รอเราถาม | **ทักเราเองได้ (เตือน/ชวน)** |

> สมองยืม Claude/GPT มา แต่ "ความจำ + เรียนรู้ตัวตน + อยู่ในไลน์ + ความไว้ใจ" คือสิ่งที่เราสร้างเอง = แก่น CS

## 5. วัตถุประสงค์ (Objectives)

1. พัฒนาผู้ช่วย AI บน LINE ที่จดจำบริบทการสนทนาข้ามเซสชันได้
2. พัฒนา **File Vault** ดาวน์โหลด+จัดเก็บไฟล์ก่อนหมดอายุ พร้อมค้นหา
3. พัฒนา **ระบบความจำระยะยาวคล้ายมนุษย์** รองรับภาษาไทย
4. พัฒนา **ระบบเรียนรู้ตัวตนผู้ใช้** (โปรไฟล์/ความชอบ/แพตเทิร์น ที่เติบโตได้) — *จิตวิญญาณของน้องยิน*
5. ออกแบบ **ความเป็นส่วนตัวและการควบคุมของผู้ใช้** (โปร่งใส + ลบได้ + ตาม PDPA)
6. เปิดความสามารถผ่าน **MCP** ให้ AI ภายนอกเรียกใช้
7. **ประเมินผลเชิงวิทยาศาสตร์** (benchmark + metrics + ablation)

## 7. สถาปัตยกรรม (Architecture)

```
        👤 ผู้ใช้ (อาจารย์/คนทำงาน) คุยผ่าน LINE
                    │  webhook (HTTPS)
                    ▼
        ┌───────────────────────────────┐
        │  LINE Bot (Frontend)          │  FastAPI + line-bot-sdk
        │  - รับ event / ตอบกลับ          │
        │  - ดาวน์โหลดไฟล์ (get-content)  │
        └───────────────────────────────┘
                    │ เรียกใช้
                    ▼
        ┌───────────────────────────────┐
        │  🧠 CORE LIBRARY (สมอง)        │  ← สร้างเอง = ส่วนที่ได้คะแนน
        │  - Fact Extraction             │
        │  - User Profile (เรียนรู้ตัวตน)  │  ← จิตวิญญาณ
        │  - Memory Decay (Ebbinghaus)   │
        │  - Hybrid Retrieval (BM25+vec) │
        │  - Summarization               │
        └───────────────────────────────┘
             │            │             │
       Vector DB     Object Storage   เปิดผ่าน
       (ความจำ)      (File Vault)     MCP Server
             │            │             │
        pgvector/     Cloudflare R2   🔌 ให้ Claude/
        Oracle 23ai                    ChatGPT/Cursor ใช้
```

**หลักการ:** ทั้ง LINE bot และ MCP server เรียกใช้ **Core Library เดียวกัน** — ห้ามเขียนโค้ดซ้ำ

## 9. ระเบียบวิธี: Memory Engine (แก่นวิชาการ)

ระบบความจำ 3 ชั้น:
1. **Short-term:** เก็บข้อความล่าสุด N ข้อความ (verbatim) ใส่ใน prompt ทุกครั้ง
2. **Summarization:** เมื่อยาวเกิน → สรุปแบบ rolling/running summary (ประหยัด token)
3. **Long-term (RAG):** ฝัง embedding → เก็บใน vector DB (key ด้วย userId) → ค้น top-k มาใส่ prompt

เทคนิคเด่น (จุดแปลกใหม่):
- **Fact Extraction:** สกัด "ข้อเท็จจริงถาวร" จากบทสนทนา (ADD/UPDATE/DELETE) แทนการเก็บข้อความดิบ
- **User Profile / เรียนรู้ตัวตน:** ต่อยอดจาก fact extraction → สร้าง "โปรไฟล์ผู้ใช้" ที่สะสมความชอบ/นิสัย/แพตเทิร์น แล้วเอามาปรับคำตอบให้ตรงใจขึ้นเรื่อย ๆ *(นี่คือส่วนที่ทำให้น้องยิน "รู้จักเรา" ไม่ใช่แค่ "จำเรา")*
- **Memory Decay:** ความจำเก่า/ไม่ถูกใช้ จางลงตามเวลา (อ้างอิง **Ebbinghaus Forgetting Curve** / exponential time-decay) — ของที่ถูกเรียกบ่อย/สำคัญคงอยู่
- **Hybrid Retrieval:** ผสม BM25 (keyword) + vector (semantic) ให้ค้นแม่นขึ้น
- **ภาษาไทย:** embeddings ที่รองรับไทย (BGE-M3) + จัดการตัดคำ (ไทยไม่มีเว้นวรรค = ปัญหายาก = จุดวิจัย)

## 10. ความเป็นส่วนตัว & ความไว้ใจ (Privacy & Trust) — จุดที่ทำให้คนกล้าใช้

> หลายคนหวง/กลัวการให้บอทจำเรา — คำตอบไม่ใช่ "อย่าจำ" แต่คือ "ทำให้ผู้ใช้ไว้ใจและควบคุมได้"

หลักการออกแบบ 3 ข้อ:
1. 🔍 **โปร่งใส** — ผู้ใช้สั่งได้ว่า *"น้องยินจำอะไรเกี่ยวกับฉันบ้าง?"* แล้วมันแสดงให้ดู
2. 🗑️ **ควบคุมได้** — ผู้ใช้สั่ง *"ลืมเรื่องนี้ให้หน่อย"* แล้วลบจริง (เชื่อมกับ Memory Decay + DELETE ใน fact extraction)
3. 💝 **เพื่อตัวผู้ใช้เอง** — ความจำมีไว้ช่วยผู้ใช้ ไม่เอาไปขาย

→ สอดคล้องกับ **PDPA** (ข้อ 12) พอดี: consent + privacy notice + สิทธิ์ขอลบข้อมูล
→ เขียนเรื่องนี้ในรายงาน + พูดตอน defense = ได้คะแนนความรอบคอบ และตอบคำถามกรรมการเรื่อง "คนจะยอมใช้ไหม" ได้

## 11. การวัดผล (Evaluation) — ห้ามตัด!

นี่คือสิ่งที่เปลี่ยน "โปรแกรม" เป็น "งานวิจัย":
- **Benchmark:** สร้างชุดทดสอบภาษาไทยเอง หรืออ้างแนว **LoCoMo / LongMemEval**
- **Metrics:** recall@k, precision@k, MRR, nDCG (การค้นคืน) + ความแม่นการตอบ (F1 / LLM-judge) + latency (p50/p95) + tokens/query
- **Ablation study:** เปรียบเทียบ มี/ไม่มี memory decay, BM25-only vs vector-only vs hybrid, มี/ไม่มี fact extraction
- → มีตาราง/กราฟในรายงาน

## 12. ⚠️ ข้อจำกัด & กับดักสำคัญ (ตรวจสอบแล้ว — อ่านก่อนเขียนโค้ด!)

### LINE Messaging API
- **Reply token หมดอายุ ~60 วินาที + ใช้ครั้งเดียว** → LLM ต้องตอบเร็ว / โชว์ loading / ถ้าช้าต้องใช้ push (เปลืองโควต้า)
- **Reply messages ฟรีไม่จำกัด** แต่ **Push/broadcast จำกัด ~200-500/เดือน** → ออกแบบให้ "ตอบกลับ" เป็นหลัก
- **บอทอ่านได้เฉพาะแชต/กลุ่มที่บอทเป็นสมาชิก** (กำแพง privacy)
- ในกลุ่มที่บอทอยู่ → ได้รับทุกข้อความ แต่ต้องตั้งค่า (Allow bot to join group chats + Bot mode + webhook)
- ต้องมี **HTTPS endpoint ที่มี CA cert** (self-signed ไม่ได้)

### File Vault — ขอบเขตที่ต้องสื่อสารตามจริง
- ดาวน์โหลดผ่าน `GET https://api-data.line.me/v2/bot/message/{messageId}/content` **ทันที**ที่ไฟล์เข้ามา
- ⚠️ **เก็บได้เฉพาะไฟล์ที่ส่งหาบอท / ในกลุ่มที่บอทอยู่** — **ไม่ใช่ backup ทั้ง LINE**
- ใช้ได้เมื่อ `contentProvider.type == "line"` เท่านั้น
- ไฟล์อาจถูกบีบอัด (ไม่ byte-perfect เสมอ) / วิดีโอ-เสียงใหญ่อาจคืน HTTP 202 (ต้องเช็ก status)
- **มี LINE Developers Thailand tutorial ทางการ** (ค้น "linedevth media cloud storage")

### Hosting ฟรี 24/7 (กับดักใหญ่)
- **Render free** = หลับหลังไม่มีคน 15 นาที → cold start 30-60 วิ (ชนกับ reply token 60 วิ!)
- **แนะนำ:** Google Cloud Run (scale-to-zero) หรือ Koyeb
- Railway/Fly.io **ไม่ฟรีแล้ว** สำหรับ 24/7

### LLM / Search free tier
- Gemini free tier จำกัด + **ข้อมูลฟรีอาจถูกใช้ train** → ระวังข้อมูลส่วนตัว (เชื่อมกับเรื่อง privacy ข้อ 10!), ใช้ Vertex/paid หรือ Ollama local ถ้าต้อง opt-out
- **Web Search API ฟรียากปี 2026:** เหลือ **Tavily** (~1,000/เดือน) หรือ self-host **SearXNG**
- **YouTube transcript:** YouTube บล็อก IP cloud → รันบน server ฟรีจะล่ม + ขัด ToS

### กฎหมาย
- **PDPA:** เก็บข้อความ/ไฟล์ = ข้อมูลส่วนบุคคล → ต้องมี consent + privacy notice + ลบข้อมูลได้
