# Next.js + PWA

## คืออะไร
Next.js คือเฟรมเวิร์กสร้างหน้าเว็บด้วย React + TypeScript — เราใช้มันสร้าง "จีนรู้ใจ" ให้เป็น **PWA (Progressive Web App)** คือเว็บที่กดติดตั้งลงมือถือเป็นไอคอนแอปได้ และเปิดใช้ได้แม้ไม่มีเน็ต

## ทำไมต้อง PWA ไม่ทำแอปเนทีฟ
- ทีม 2 คน 4 เดือน งบ 0 — เขียนโค้ดชุดเดียวใช้ได้ทุกเครื่อง ไม่ต้องทำ iOS/Android แยก
- ไม่ต้องผ่าน App Store (ไม่มีค่าธรรมเนียม ไม่ต้องรอรีวิว)
- แจกลิงก์ให้ผู้ทดสอบได้ทันที — สำคัญเพราะเราต้องเก็บข้อมูลผู้เรียนไทยไปเทรน [[pyBKT]]

## ชิ้นส่วนหลักฝั่งหน้าเว็บ

| ตัว | ทำอะไร |
|---|---|
| **Serwist** | สร้าง Service Worker = "ผู้ช่วยเบื้องหลัง" ที่ก็อปหน้าเว็บ+บทเรียนเก็บในเครื่อง → ออฟไลน์ได้ + ติดตั้งได้ |
| **Dexie** | ตัวช่วยใช้ IndexedDB (ฐานข้อมูลในเบราว์เซอร์) เก็บบัตรคำ/ประวัติการตอบตอนไม่มีเน็ต |
| Tailwind | จัดหน้าตา CSS แบบเร็ว |
| Zustand | เก็บ state ในแอป (เบากว่า Redux) |
| Recharts | วาดกราฟ Dashboard ความแม่นรายทักษะ |
| ts-fsrs | รัน [[FSRS]] ฝั่ง client ได้ตอนออฟไลน์ |

⚠️ **อย่าใช้ next-pwa** — ไลบรารีเก่าตัวนั้นตายแล้ว (เลิกพัฒนา) → ใช้ **Serwist** ซึ่งเป็นตัวสืบทอดแทน

## ออฟไลน์ทำงานยังไง (สำคัญ)
1. Service Worker (Serwist) เก็บ "ตัวแอป" — หน้าเว็บ บทเรียน เสียงอ่านที่ pre-generate ไว้
2. Dexie/IndexedDB เก็บ "ข้อมูล" — บัตรคำ + ทุกการตอบถูก/ผิดระหว่างไม่มีเน็ต
3. พอกลับมาออนไลน์ → sync ข้อมูลขึ้น [[Supabase]]

จำหลักนี้ไว้: **IndexedDB = ที่พักชั่วคราว · Supabase = ตัวจริง** — ข้อมูลการตอบทุก log มีค่ามาก เพราะใช้เทรน [[pyBKT]] ด้วยข้อมูลคนไทยเราเอง

## ⚠️ ข้อจำกัด iOS ที่ต้องรู้
Safari/iOS อาจ**ลบข้อมูลเว็บ (รวม IndexedDB) ถ้าผู้ใช้ไม่เปิดแอปนาน ~7 วัน** → เป็นอีกเหตุผลว่าทำไมต้อง sync ขึ้น Supabase บ่อย ๆ ห้ามหวังพึ่ง IndexedDB เป็นที่เก็บถาวร

## เกี่ยวข้องกับ
- [[FastAPI]] — หน้าเว็บยิง API ไปหา backend ตัวนี้
- [[Supabase]] — ปลายทาง sync ข้อมูลตัวจริง
- [[โฮสติ้งฟรี]] — deploy บน Vercel/Cloudflare Pages
- [[FSRS]] · [[pyBKT]] — สมองที่หน้าเว็บนี้เป็นหน้ากากให้
