## 1️⃣ คำสั่ง/การบ้านจากอาจารย์ (เรียงตามความสำคัญ)

### 🔴 ต้องมีก่อนนัดหน้า
1. **"กรอบซอฟต์แวร์" ที่ชัดเจน** — ตอนนี้ "มันไม่มีกรอบ" (คำอาจารย์เอง) ต้องตอบได้ว่า ระบบประกอบด้วยอะไรบ้าง มีกี่ content แต่ละ content มีอะไร → ดู `docs/08_สเปค-พัฒนา/กรอบระบบ-CHECKLIST.md` (ทำแล้ว)
2. **Checklist + timeline รายเดือน** — ตารางติ๊กความคืบหน้า ส่งให้อาจารย์ดูเป็นระยะ
3. **เดดไลน์: สิงหาคม = พร้อมสอบ 50% (midterm)** — หลักคือ "ขึ้นโครงครบทุกส่วนก่อน เนื้อหา/ศัพท์ไม่ครบได้ ค่อยเติม" + ไปเช็กกำหนดสอบ 50%/100% ทางการของภาค

### 🟠 โครงสร้างระบบที่อาจารย์กำหนด
4. **โมเดล 2 มิติ: Content (หมวด) × ทักษะ** — หน้าแรกเลือกหมวด (ครอบครัว อาหาร เวลา ชีวิตประจำวัน เดินทาง สถานที่ ฯลฯ) ข้างในฝึกรายทักษะ · ต้องตอบได้ว่ากี่หมวดพอ + ศัพท์กี่คำ/หมวด (เช่น 300÷6 ≈ 50)
5. **เอา 3 ทักษะก่อน: ฟัง อ่าน เขียน** — "ส่วนอันอื่นเป็น option" (พูด = ไม่บังคับ ✅ ตรงสโคปเดิมเรา)
6. **ฟังไล่ระดับ: วรรณยุกต์ → คำ → ประโยค** — อาจารย์ย้ำเอง "วรรณยุกต์...ตัวเนี้ยสำคัญ" (✅ ตรง Thai-L1/minimal pair ที่วางไว้เป๊ะ)
7. **ระบบ = เรียน + สอบ** (เรียนอย่างเดียวไม่พอ วัดผลไม่ได้) และ **การอ้างระดับ HSK ต้องวัดจากการทำข้อสอบเท่านั้น**
8. **วัดผล 2 ชั้น:** (ก) คะแนนระหว่างเรียน → % ความสำเร็จราย content ("ผ่านครบ 5 content → น่าจะสอบผ่านกี่ %") (ข) คะแนนสอบ = ตัวชี้ขาด → 💡 **ข้อ (ก) คือสิ่งที่ BKT mastery ทำอยู่แล้วเป๊ะ** — นัดหน้าต้องนำเสนอให้อาจารย์เห็นว่าเราวางไว้แล้ว
9. **บทบาท 2 ระดับ: Member + Admin** — Admin จัดการ "บทเรียน + แบบทดสอบ" (เพิ่ม/ลบ/แก้) ← **โมดูลใหม่ที่ไม่อยู่ในแผนเดิม** (admin = ทีมเราเอง 2 คน)
10. **แยก content HSK1 / HSK2 คนละชุด** (เพื่อนโหวตแยก อาจารย์โอเค — แบบไหนก็ได้แต่ต้องชัด)

### 🟡 เนื้อหา/อ้างอิง
11. **HSK เวอร์ชันไหนก็ได้ (2.0/3.0) แต่ต้องมี reference ชัด อธิบายกรรมการได้** — ทีมเอนไป 3.0 · หมายเหตุ: ในที่ประชุมตัวเลขยังสับสน (อาจารย์เข้าใจ 500/1,000 · เพื่อนอ้าง ~1,270) → เรามี reference ยืนยันแล้ว: **3.0 = L1 300 / L2 500 สะสม** (ดู [[HSK-3.0-ข้อเท็จจริง]]) เตรียมแผ่นเดียวโชว์นัดหน้า
12. **อิงหนังสือเรียน HSK/เว็บทางการเป็น reference** แล้วแปลงเป็นเนื้อหาเราเอง (อาจารย์เตือนเองเรื่องลิขสิทธิ์ "เสี่ยงนิด ๆ") — ของเรา: ใช้ sample ทางการเป็นแม่แบบ format เท่านั้น + เนื้อหาสร้างเอง+หฤทัยตรวจ (ทำอยู่แล้ว)
13. **Pacing สมจริง: 10–20 คำ/วัน** (อาจารย์คำนวณโชว์ว่า 100–200 คำ/วันเป็นไปไม่ได้) → ใช้ตั้งค่า "คำใหม่/วัน" ใน FSRS (ตอนนี้เราตั้ง 10/วัน ✅ ตรงแล้ว)

### 🟢 อื่น ๆ
14. **ทดสอบกับผู้ใช้จริงผ่านครูสอนภาษาจีน** — เพื่อนของตะวันเป็นครูจีน + อาจารย์มีน้องเป็นครูจีน · แผนคร่าว: **5 โมดูล เรียนวันละโมดูล+สอบ ~10 วัน เก็บคะแนนจริง** → 🎯 นี่คือทางแก้คอขวด "หาผู้ทดสอบ" + แหล่ง log เทรน BKT!
15. **การบ้าน AI:** อ่านเอกสาร Multi-agent ที่อาจารย์ส่งทาง LINE + ลองเล่น Ollama (เครื่องบอลมี GPU) → นัดคุย "AI สักประเด็น" เป็นจุดขาย · อาจารย์กำกับชัด: **"ขอกรอบให้ชัดก่อน แล้วค่อยเรื่อง AI"**
16. เอกสาร: proposal บท 1–3 **ยังไม่ต้องทำคู่ขนานตอนนี้** · ดูเล่มรุ่นพี่ในห้องสมุดเป็นแนว · อาจารย์จะส่งตัวอย่าง paper ให้ · สงสัยทัก LINE ได้เลย
17. **เปลี่ยนเสียง TTS** (จากทีมเอง — ตะวันบอกเสียงปัจจุบัน "อ่อน/ไม่ชัด")
18. 🔴 **ซ้อมตอบ tech stack** — ในคลิปบอลตอบคำถาม "ใช้ภาษาอะไร/เครื่องมืออะไร" ไม่ได้ อาจารย์ย้ำว่าตอนสอบโดนถามแน่ · คำตอบมาตรฐาน: **Next.js (React) + TypeScript + Tailwind + Supabase (PostgreSQL) + FastAPI (Python) · deploy Vercel + Render · PWA ติดตั้งบนมือถือได้**

## 3️⃣ Tensions — จุดที่ต้องจัดการอย่างมีชั้นเชิง
1. **กลุ่มเป้าหมาย:** อาจารย์วางแอปเป็น "ตัวซัพพอร์ตเด็กที่มีพื้นจากห้องเรียน" vs สโคปเดิม "จาก 0" → จริง ๆ ประนีประนอมได้: นักเรียนที่ครูพาใช้ = ผู้เริ่มต้นเกือบ 0 อยู่ดี · เสนอเขียนกลุ่มเป้าหมายเป็น "ผู้เริ่มเรียน (0 หรือใกล้ 0) ที่เตรียม HSK 1–2 — ใช้เดี่ยวหรือครูใช้เสริมในห้อง" ครอบทั้งสองภาพ
2. **AI เป็นจุดขาย (Ollama/Multi-agent/แนะนำออกเสียง):** ชนกับกติกา rule-based + ตัดพูด · **ท่าตอบ 3 ชั้น:** (ก) เราใช้ multi-agent จริงแล้วใน pipeline สร้าง/ตรวจเนื้อหา (Thai-L1 catalog + รีเสิร์ช 48 ฟีเจอร์ = adversarial verification จริง โชว์ได้) (ข) แกน BKT/FSRS ก็คือ ML/AI — อาจารย์ยังไม่เห็นภาพนี้ ต้องนำเสนอ (ค) แนะนำการออกเสียง: ทำแบบไม่ต้อง ASR ได้ = minimal pair ฝึกหู + วิดีโอรูปปาก (ตามที่อาจารย์เปรยเรื่องรูปปาก — หา/ฝังของฟรี) ส่วนวิเคราะห์เสียงพูดจริง = future work ตามที่เคยตกลง
3. **เขียน stroke order:** อาจารย์บอก optional/challenge ตัดได้ถ้ายาก · **เรามีข้อมูลใหม่ที่ทีมยังไม่รู้ตอนประชุม:** HSK2 ระบบ 3.0 มีสอบเขียนจริง 10 ข้อ (พินอิน→เขียน จากลิสต์ 100 ตัว) — ในคลิปบอลตอบ "เหมือนมีแต่ไม่แน่ใจ" เพื่อนบอก "ตอนสอบไม่ได้เขียน" (เธอสอบ 2.0 — ถูกทั้งคู่!) → นัดหน้าเอาคำตอบชัด ๆ ไปเฉลย + เสนอ: ทำเป็นโมดูล optional เป้า HSK2 (bounded แค่ 100 ตัว, มี Hanzi Writer โอเพนซอร์ส)
4. **Netlify (อาจารย์เปรย) vs Vercel (เราใช้):** อธิบายได้ — ประเภทเดียวกัน เราเลือก Vercel เพราะเป็นเจ้าของ Next.js รองรับ native
5. "การอ่านให้เสียงเราเข้าไป" (บรรทัด ~109) — STT กำกวม อย่าเพิ่งถือเป็นคำสั่ง ASR; ตีความว่า "มีเสียงอ่านให้ฟังตอนอ่าน" สมเหตุผลกว่า
