# สรุปพบอาจารย์ — นัดตรวจวันจันทร์ 13 ก.ค. 2026 (ถอดจากบันทึกเสียง)

> ที่มา: บันทึกเสียงในห้อง (ASR ถอดเสียง มีเพี้ยนบ้าง) · สรุป/จัดหมวดโดย AI วันที่ 16 ก.ค. 2026
> ถ้าวันที่หรือประเด็นไหนคลาดจากที่ได้ยินจริง แก้ในไฟล์นี้ได้เลย

## TL;DR — สิ่งที่อาจารย์ย้ำที่สุด

**"ตอนนี้มันยังไม่มีกรอบ"** — ก่อนเพิ่มฟีเจอร์ ให้ถอยกลับมานิยาม**โครงสร้างระบบ**ให้ชัดก่อน
แล้วทำเป็น **checklist + timeline** เอามาให้อาจารย์ดูทุกนัด

- **สิ้นเดือน ก.ค.** → ต้องได้ "กรอบซอฟต์แวร์" ที่ชัดเจน (ยังไม่สมบูรณ์ได้ ศัพท์ไม่ครบได้ แต่โครงต้องครบ)
- **ส.ค.** → พร้อมสอบ 50% (midterm) — ไปเช็กวันสอบจริงจากหลักสูตรด้วย
- เอกสารเล่ม (บท 1–3) **ยังไม่ต้องทำตอนนี้** — เอากรอบก่อน · อาจารย์จะส่ง template paper มาให้ · ดูรูปแบบเล่มรุ่นพี่ในห้องสมุด · สงสัยทัก LINE อาจารย์ได้เลย

## 1) โครงสร้าง Content (หมวดเนื้อหา)

- กำหนดให้ชัดว่ามี**กี่ content** เช่น เรียนรู้ภาษาจีน / ครอบครัว / อาหาร / เวลา / ชีวิตประจำวัน / การเดินทาง / สถานที่ — แค่นี้พอไหม หรือต้องเพิ่ม
- ตัดสินใจว่า **HSK 1 กับ HSK 2 แยก content หรือรวมกัน** — แบบไหนก็ได้แต่ต้องชัดเจนและอธิบายเหตุผลได้
- แต่ละ content ต้องระบุได้ว่า**ครอบคลุมคำศัพท์กี่คำ** รวมแล้วครบตามเกณฑ์เวอร์ชันที่อ้างอิง

## 2) ทักษะในแต่ละ content — ฟัง อ่าน เขียน (เอา 3 ทักษะนี้ก่อน ที่เหลือเป็น option)

ทุกทักษะให้ไล่ระดับ: **เสียง/วรรณยุกต์ → คำ → ประโยค** และแยกให้ชัดว่า HSK 1 กับ HSK 2 ต่างกันยังไง (อิงเกณฑ์ทางการ อธิบายได้ว่า "ทำไมเป็นแบบนี้")

- **ฟัง** — เริ่มจากเสียง+วรรณยุกต์ (อาจารย์เน้นว่าสำคัญ) → คำ → ประโยค/บทสนทนา · รูปแบบวัด: ฟังแล้วเลือกตอบ (เช่น ฟังบทสนทนา ตอบว่าใครกินข้าวแล้ว) — หฤทัยอธิบายรูปแบบข้อสอบจริงให้อาจารย์ฟังแล้ว อาจารย์โอเค
- **อ่าน** — HSK 1 อาจเป็นระดับคำ, HSK 2 คำ+ประโยค → ไปดูเกณฑ์ทางการแล้วนิยาม
- **เขียน** — ของที่มีตอนนี้ (เลือกคำ/เรียงประโยค) อาจารย์บอก "จัดเป็นการเขียนได้" แต่ให้ไปนิยามให้ชัดว่า "เขียน" ของเราหมายถึงอะไรตามเกณฑ์ HSK · การเขียนจริง (ลำดับขีด/ทิศทางขีด) อาจารย์ยอมรับว่า**ยาก — ถ้ายากเกินตัดได้ ไม่ต้อง complete ทุกอย่าง** แต่ถ้าทำได้ก็เป็น challenge (หมายเหตุทีม: HSK1 ระบบ 2.0/3.0 ไม่มีพาร์ตเขียนอักษร — ดูโน้ต HSK-3.0-ข้อเท็จจริง)

## 3) Reference — ต้องอ้างอิงได้ทุกอย่าง

- **เลือกเวอร์ชัน HSK ให้ชัด** — "เอาเวอร์ชันไหนก็ได้ แต่ต้องมี reference และอธิบายตอนสอบได้"
  - 🔄 **แก้ตัวเลขให้ตรงข้อเท็จจริงที่ verify แล้ว (22 ก.ค. — ดู [[HSK-3.0-ข้อเท็จจริง]]):** ระบบ **2.0: HSK1 = 150 / HSK2 = 300** · ระบบ **3.0 ลิสต์ข้อสอบจริง: HSK1 = 300 / HSK2 = 500 สะสม** (ส่วนเลข 500/1,272 ที่พูดกันในห้อง = band มาตรฐาน GF0025 ไม่ใช่ลิสต์ข้อสอบ — อย่าใช้ปนกัน)
  - ✅ **ทีมเคาะแล้ว (22 ก.ค. — บอล): ยึด HSK 3.0 เป็น reference หลัก** (= คลัง 300 คำใน DB + PRD ที่สร้างไว้แล้ว) · เหตุผล: มาตรฐานทางการบังคับใช้แล้ว + ครอบคลุมลิสต์ 2.0 (150 คำ) ที่สนามสอบปีนี้ใช้ → รายละเอียด+บทตอบอาจารย์: [[กรอบระบบ-จากอาจารย์]] · หฤทัยช่วยเตรียมลิงก์ reference (大纲/CLEC) ประกอบ
- **อิงหนังสือเรียน/แหล่งทางการสักแหล่ง**เป็นแนวเนื้อหา-วิธีสอน แล้วแปลงเป็นเนื้อหาของเรา (ใช้ AI ช่วยเรียบเรียงใหม่ได้ ไม่ก๊อปตรง) — จะได้มี reference ว่าแนวการสอนอิงจากไหน

## 4) การวัดผล — 2 ชั้น

1. **วัดจากการเรียน** (ไม่ต้องสอบ): คะแนนสะสมต่อ content → คิดเป็น % ความพร้อม เช่น ผ่าน 5 content ได้ 25/50 = "ความพร้อมสอบ HSK1 ~50%"
2. **แบบทดสอบ / ข้อสอบ mock**: ใช้ข้อสอบ HSK ที่เผยแพร่แบบไม่ติดลิขสิทธิ์ — จะสอบท้ายแต่ละ content หรือรวมตอนจบก็ได้ ไปออกแบบมา
- ระวังปริมาณ: เรียน+สอบเยอะไปจะน่าเบื่อ — จัดให้พอดี

## 5) ระบบต้องมี Member + Admin (requirement ใหม่ที่ชัดจากอาจารย์)

- **Member**: สมัครสมาชิก / ล็อกอิน — ไม่งั้นไม่รู้ว่าใครเรียนถึงไหน (เก็บ progress รายคน)
- **Admin**: จัดการคำศัพท์ (เพิ่ม/ลบ/แก้ไข) + **จัดการบทเรียน** + **จัดการแบบทดสอบ** — สิทธิ์แยกจาก member

## 6) การบ้านด่วนของบอล — ต้องตอบได้ว่าใช้เทคโนโลยีอะไร

อาจารย์ถาม "เขียนด้วยภาษาอะไร ใช้เครื่องมืออะไร" แล้วทีมตอบไม่ได้ → อาจารย์เตือนตรง ๆ ว่า**ตอนสอบโดนถามแน่ "ไม่ใช่ว่าให้ AI พัฒนาให้แล้วไม่รู้ว่ามันคือภาษาอะไร"**

คำตอบที่ต้องท่องให้ขึ้นใจ (ของจริงในโปรเจกต์):
- ภาษา: **TypeScript** (ซูเปอร์เซ็ตของ JavaScript) + Python ฝั่ง API
- Frontend: **Next.js** (React framework) + Tailwind CSS · ทำเป็น **PWA** ติดตั้งลงมือถือได้ (Mobile Responsive)
- Backend: **FastAPI (Python)** · DB: **Supabase (PostgreSQL, on cloud)** — อาจารย์รับทราบแล้วว่าใช้อยู่ มีศัพท์ 300 คำใน DB แล้ว
- Deploy: ปัจจุบันใช้ **Vercel** (เว็บ) + **Render** (API) · อาจารย์แนะนำ **Netlify** — จดไว้เป็นตัวเลือก/เตรียมอธิบายว่าทำไมใช้ Vercel

## 7) แผนทดสอบกับผู้ใช้จริง (ตอนระบบเสร็จ)

- วางตำแหน่งเป็น **"สื่อเสริม" (support)** สำหรับผู้เรียน ไม่ใช่สอนแทนครู
- ช่องทางมีแล้ว: เพื่อนหฤทัยเป็นครูสอนภาษาจีน + น้องอาจารย์ก็สอนภาษาจีน
- รูปแบบที่อาจารย์เสนอ: ~**5–10 วัน** เรียนวันละ 1 โมดูล + สอบท้ายโมดูล เก็บคะแนน pre/post
- เรื่อง pacing ให้คิดตามจริง: วันละ 100 คำไม่มีใครจำได้ — **~20 คำ/วันก็หนักแล้ว** (เสียงจีนคล้ายกัน จำวันนี้พรุ่งนี้ลืมเป็นเรื่องปกติ)
- ข้อจำกัดที่อาจารย์ชี้: ซอฟต์แวร์ไม่เห็น "รูปปาก" แบบครูจริง — ถ้าอยากอัปเกรดค่อยมีวิดีโอประกอบ (future work)

## 8) AI — การบ้านศึกษา 2 เรื่อง แล้วนัดคุยรอบหน้า

อาจารย์มองว่าเนื้อหาอย่างเดียว "ไม่มีความทันสมัย ไม่ challenge" → ให้ไปเล่น 2 อย่างที่อาจารย์ส่งให้ แล้วมาคุยกันว่าจะหยิบ AI เข้ามาช่วย**สัก 1 ประเด็น**เป็นจุดขาย (ไม่ใช่ทั้งระบบ):
1. **Ollama** — รัน LLM ในเครื่อง (เครื่องมี GPU Nvidia อยู่แล้ว ใช้ให้เป็นประโยชน์)
2. **Multi-agent** — agent ควบคุม LLM อีกชั้น (แนว Claude Code / Codex)

> หมายเหตุทีม: จุดขาย AI/ML ของเรามีอยู่แล้วใน PRD — **pyBKT (Knowledge Tracing) + วินิจฉัย Thai-L1 + FSRS** — รอบหน้าควรนำเสนอให้อาจารย์เห็นว่านี่คือแกน AI ของเรา แล้วค่อยต่อยอดด้วย Ollama/multi-agent ในจุดที่เหมาะ (เช่น สร้างเฉลย/คำอธิบายภาษาไทย)

## 9) เรื่องย่อยอื่น ๆ

- **เสียง TTS ปัจจุบันอ่อน/ไม่ชัด** (หฤทัยยืนยัน) → หาเสียงใหม่
- ให้เอาฟีเจอร์ที่รีเสิร์ชมา **"ประกบ"** กับตารางโครงสร้างที่อาจารย์ร่างให้ (content × ทักษะ) ว่าแต่ละอันลงช่องไหน
- ตัวเลือกคำตอบ: อาจต้องมีทั้ง**พินอินและตัวอักษรจีน** ให้เลือก — ไปดูรายละเอียด
