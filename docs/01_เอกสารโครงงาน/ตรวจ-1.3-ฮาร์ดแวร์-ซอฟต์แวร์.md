## สรุปสั้น

**ร้ายแรงที่สุด 2 เรื่อง (คนละชนิดกัน):**

1. **ไม่ใช่แค่เรื่องเอกสาร — pyBKT บน Windows ให้ผลผิดแบบเงียบ ๆ**
   1.3.1 ระบุโน้ตบุ๊ก Windows 2 เครื่อง คู่กับ 1.3.3 ที่ระบุ pyBKT — บน Windows ติดตั้งได้เฉพาะเวอร์ชัน pure Python ซึ่งมีบั๊ก (บล็อก E-step ถูกครอบด้วย `if __name__ == "__main__":` ที่ไม่มีวันเป็นจริง) ทำให้ `fit()` คืน prior = NaN และ guess/slip ค้างที่ 0.5 → **AUC ออกมา ≈ 0.5 เท่าเดาสุ่ม โดยโปรแกรมไม่ error เลย**
   บั๊กแก้แล้วบน master (issue #62 / PR #63) แต่ PyPI ยังเป็น 1.4.2 ที่ยังไม่มีตัวแก้
   → **ต้องฝึกโมเดลบน WSL2 หรือ Google Colab เท่านั้น** และทำ sanity check ทุกครั้งก่อนเชื่อตัวเลข
   ⚠️ ข้อนี้ควรทดสอบมือเองก่อนเชื่อ 100% — รัน `fit()` กับข้อมูลตัวอย่างเล็ก ๆ บน Windows แล้วดูว่าค่าที่ได้เป็น NaN/0.5 จริงไหม (ใช้เวลา ~5 นาที)

2. **เรื่องเอกสาร — 1.3.4 ขัด "กฎเหล็ก" ของทีมเอง**
   เขียนแค่ "LLM (Gemini/Typhoon) แบบ stateless" ไม่มีคำว่า "ส่วนเสริม" หรือ "ไม่ใช้ตรวจคำตอบ" เลย ขณะที่ PRD/ARCHITECTURE/feedback อาจารย์ยึดว่าตรวจด้วย rule เทียบเฉลย 100% ห้าม LLM ตัดสิน
   ซ้ำร้าย `ARCHITECTURE.md:327` อ้าง "proposal §1.3.4" เป็นที่มาของกฎ "LLM = เสริมเท่านั้น" ทั้งที่ 1.3.4 ไม่ได้เขียนคำนั้นไว้ — เอกสารอ้างวนกันเองโดยไม่มีของจริงรองรับ

**ภาพรวม:** 1.3 ระบุของที่ไม่ได้ใช้ (SQLite, makemeahanzi, py-fsrs) และไม่ระบุของที่ใช้จริง (Supabase, Tailwind, ts-fsrs, Vercel/Render) = "ผิดสองทาง" ในหัวข้อเดียว ซึ่งกรรมการจับได้ง่ายที่สุดเพราะแค่ขอดูโค้ดก็เห็น

- pandas และ NumPy — จัดเตรียมข้อมูลบันทึกการตอบสำหรับฝึกแบบจำลองผู้เรียน

- บันทึกการตอบของผู้เรียนชาวไทยที่ระบบเก็บเอง — ข้อมูลหลักที่ใช้ฝึกแบบจำลองผู้เรียน
  โดยขอความยินยอมจากผู้เข้าร่วมตามกฎหมายคุ้มครองข้อมูลส่วนบุคคล

หมายเหตุ: เลขเวอร์ชันที่ระบุเป็นเวอร์ชัน ณ วันจัดทำเอกสาร อาจปรับเป็นรุ่นใหม่กว่าระหว่าง
การพัฒนาโดยไม่กระทบขอบเขตของโครงงาน

**เหตุผลที่อธิบายกรรมการได้ว่าไม่ใช่การเปลี่ยนสโคป:** ทุกการเพิ่มเป็นการ **ระบุรายละเอียดของสิ่งที่เขียนไว้แล้ว** ให้ตรงกับของที่ใช้จริง (Supabase คือ "PostgreSQL" ที่เล่มเขียนไว้อยู่แล้ว · Vercel/Render คือคำตอบของ "งบ 0 บาท" ที่เล่มอ้างอยู่แล้ว · Serwist/Dexie คือกลไกของ "PWA/ออฟไลน์" ที่ 1.2.1 อ้างอยู่แล้ว) ส่วนการตัด (SQLite, makemeahanzi) เป็นการตัดของที่ไม่ได้ใช้ออก ไม่ได้เพิ่มภาระงาน · เพิ่ม 1.3.6 กับ 1.3.7 ต่อท้าย จึง **ไม่ทำให้เลขหัวข้อ 1.3.1–1.3.5 เดิมเลื่อนแม้แต่ข้อเดียว**

## ข้อที่ตัดสินใจไม่แก้ และเหตุผล

| ไม่ทำ | เหตุผล |
|---|---|
| **ไม่ใส่ไมโครโฟน ไม่ใส่ไลบรารีวิเคราะห์เสียง** | ทีมมีมติแล้วว่า ASR และการวิเคราะห์เส้นเสียงเป็น future work — 1.3 ที่ไม่มีเครื่องมือเสียงจึง**ถูกตามมติ** ตัวที่ผิดคือ 1.5.1 ที่ยังโฆษณาโมดูลนี้ไว้ |
| **ไม่ใส่ hanzi-writer และไม่ใส่ makemeahanzi กลับ** | เป็น P2 ยังไม่ได้ติดตั้ง และ 1.5.1 ไม่ได้สัญญาเรื่องลำดับขีดไว้ · ถ้าใส่แล้วทำไม่ทัน จะถูกถามหา |
| **ไม่ใส่ Recharts และ Zustand** | อยู่ในสถาปัตยกรรมแต่ยังไม่ได้ติดตั้งใน package.json — เขียนไปคือเคลมเกิน |
| **ไม่เขียน localStorage ลงเล่ม** | เป็นวิธีเก็บชั่วคราวของต้นแบบ · แต่แลกกับข้อนี้คือ **ต้องติดตั้ง Dexie จริงก่อนวันสอบ** |
| **ไม่ใส่ Playwright / pytest / vitest** | ยังไม่มีในรีโป — ใส่แล้วกรรมการขอดูผลทดสอบจะไม่มีให้ดู |
| **ไม่แยก 1.3.2 เป็นสองหัวข้อย่อย** | จะทำให้เลข 1.3.3–1.3.5 เลื่อนทั้งชุดในเล่มที่เซ็นแล้ว โดยได้ประโยชน์น้อย |
| **ไม่คง Typhoon ไว้คู่ Gemini** | Typhoon เป็นโมเดล**ภาษาไทย**ของ SCB 10X (model card ระบุ Thai/English ไม่มีจีน) จะถูกถามว่า "เอาโมเดลภาษาไทยมาสอนภาษาจีนทำไม" · เก็บไว้ตอบปากเปล่าว่าออกแบบให้สลับ provider ได้ |
| **ไม่ตัดคำว่า stateless ทิ้ง** | อยู่ในเล่มที่เซ็นแล้ว การลบดูเหมือนเปลี่ยนสาระ · เลือก "ขยายความ" แทน โดยผูกกับเหตุผลจริงคือความเป็นส่วนตัวของข้อมูลผู้เรียน |
| **ไม่ใส่ URL ระบบจริงลงในเล่ม** | ที่อยู่เว็บอาจเปลี่ยนได้ และไม่ใช่ธรรมเนียมของหัวข้อ 1.3 · เตรียมไว้ตอบปากเปล่า/ใส่สไลด์แทน |
| **ไม่เขียนว่า Microsoft บล็อก IP ดาต้าเซ็นเตอร์** | ยืนยันไม่ได้จากแหล่งทางการ — ตามกติกาทีมห้ามอ้างข้อเท็จจริงที่ยังไม่ตรวจสอบ |
