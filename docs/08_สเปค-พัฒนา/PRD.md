## 1. ภาพรวมผลิตภัณฑ์

**Pitch:** แอปติว HSK ทั่วไปสอนเหมือนกันทุกชาติ ไม่รู้ว่า "คนไทย" พลาดตรงไหนเพราะภาษาไทย — 星航เป็นเว็บแอป (PWA) ที่ใช้ Knowledge Tracing (pyBKT) วัดความแม่นรายทักษะ + คลังจุดผิด Thai-L1 วินิจฉัยว่า *พลาดเพราะอะไร* แล้วเจาะติวจนพร้อมสอบ HSK 1–2 (มาตรฐาน HSK 3.0) ผ่านจริง

**ปัญหาที่แก้:**
1. แอปในตลาดออกแบบบทเรียน "เหมือนกันทุกชาติ" ไม่คำนึงถึงภาษาแม่ (L1 transfer) ทั้งที่ภาษาแม่กำหนดรูปแบบความผิดพลาดอย่างมีนัยสำคัญ
2. การฝึกแบบ "ท่องซ้ำทั่วไป" ไม่วินิจฉัยรายบุคคลว่าอ่อนทักษะใด และไม่ผูกกับเป้าหมายวัดผลได้ (เช่น สอบผ่าน HSK)

**จุดต่างจริง 2 ข้อ (ตรวจสอบคู่แข่งปี 2026 แล้ว — Duolingo/HelloChinese/Pleco ไม่มีใครทำ):**
1. **วินิจฉัยจุดผิดตามภาษาแม่ไทย (Thai-L1 Diagnosis)** — วรรณยุกต์เสียง 2/3, พยัญชนะม้วนลิ้น zh/ch/sh/r, ไวยากรณ์ถ่ายโอน (ลำดับคำขยาย) — มีงานวิจัยรองรับทุกจุด
2. **Knowledge Tracing รายทักษะ** — pyBKT เทรนด้วย **ข้อมูลผู้เรียนไทยที่แอปเก็บเอง** (ไม่ใช่ global) + Q-matrix จับคู่ข้อสอบ↔ทักษะ

> ⚠️ ท่ายืน: **ไม่เคลมว่าดีกว่าแอปใหญ่** — เราขาย "วินิจฉัยจุดผิดคนไทย" ที่เขาไม่ทำ

**หลักเหล็กของผลิตภัณฑ์ (ข้อตกลงกับอาจารย์ — ห้ามขัด):**
- ตรวจคำตอบด้วย **rule เทียบเฉลยเท่านั้น** — ห้ามใช้ LLM ตรวจ (ทุกข้อมีเฉลยตายตัว)
- HSK 1–2 **ไม่มีสอบพูด** (HSKK บังคับตั้งแต่ระดับ 3) → **ไม่มี speech/ASR ใน MVP** — วินิจฉัยเสียงทาง "หู" ด้วย minimal pair แทน
- LLM (Gemini Flash) = **ส่วนเสริมเท่านั้น** (ช่วยสร้างเนื้อหา/แปล) เรียกจาก server, key ใน env — ไม่ใช่ส่วนที่ใช้ประเมินผลโครงงาน

## 2. เป้าหมายที่วัดได้ + Success Metrics

**เป้าหมายของระบบ:** พาคนไทย**ไม่มีพื้นฐาน (จาก 0)** → ระดับที่**สอบ HSK 1 ผ่าน**ได้ (เกณฑ์จริง: สเกล 200 คะแนน ผ่าน 120) ตามแผนการเรียนเต็ม ~8 สัปดาห์

**สิ่งที่โครงงานพิสูจน์ได้ (คนละเรื่อง — แยกให้ขาดตอนเขียนรายงาน/ตอบกรรมการ):** ภายในเวลาพัฒนา 4 เดือน วัดได้แค่ gain score จาก pre/post Mock Exam ของผู้ทดลอง 5–10 คน ที่ใช้แอปประมาณ 10 วัน บวก AUC/ablation ของโมเดล → รายงานเป็นแนวโน้มคะแนน **ไม่สรุปว่าผู้เรียนสอบผ่านได้ในระยะที่ทดลอง**

### การวัดผล 3 ระดับ

| ระดับ | วัดอะไร | ตัวชี้วัด | เกณฑ์สำเร็จ |
|---|---|---|---|
| **ผู้เรียน** | เรียนแล้วเก่งขึ้นจริงไหม | **gain score** จาก pre/post Mock Exam (สเกล 200) | คะแนน post > pre อย่างเห็นได้ชัด; ผู้เรียนที่ใช้ครบโปรแกรมมีสัดส่วนถึงเกณฑ์ 120/200 เพิ่มขึ้น |
| **โมเดล** | pyBKT ทำนายแม่นไหม + Thai-L1 ช่วยจริงไหม | **AUC บนข้อมูลผู้เรียนไทย** (train/test split, `roc_auc_score`) + **ablation** (มี vs ไม่มี KC Thai-L1) | เกณฑ์สำเร็จ: รัน ablation ได้ถูกวิธีและรายงานผลต่าง AUC · **สมมติฐาน (H1):** เวอร์ชันมี Thai-L1 ได้ AUC สูงกว่า (ค่าอ้างอิงช่วงปกติของ KT ~0.7–0.85) |
| **การตรวจ** | เชื่อผลตรวจได้ไหม | rule-based เทียบเฉลย | ถูกต้อง **100%** (ทุกข้อเฉลยตายตัว) |

### Metrics ระดับระบบ

| ด้าน | เกณฑ์ |
|---|---|
| ออฟไลน์ | แกนเรียน (บัตรคำ) + ทวน FSRS **ใช้งานได้โดยไม่มีเน็ต** หลังโหลดครั้งแรก (Service Worker + Dexie/IndexedDB + เสียง pre-generate) |
| ต้นทุน | **ฟรี 100% ทุกชั้น** — ไม่มีค่าใช้จ่ายรายเดือนใด ๆ ตลอดโครงงาน |
| ทบทวน | เทียบ retention ของ FSRS กับ baseline (SM-2/ตารางคงที่) ตอนประเมินผล |
| Benchmark pipeline | รัน pyBKT บน Duolingo SLAM 2018 เพื่อพิสูจน์ว่า pipeline ทำงานถูก (**คนละการทดลอง** กับโมเดลจริง — SLAM ไม่มีจีน/ไทย ห้ามเอามาเทรนต่อ) |

## 3. กลุ่มเป้าหมาย + Persona

**กลุ่มเป้าหมายหลัก:** คนไทยที่**ไม่มีพื้นฐานภาษาจีน** ต้องการเตรียมสอบ **HSK 1** (ขยายถึง HSK 2) — นักเรียนมัธยม/นักศึกษา/คนทำงานที่ใช้ HSK ยื่นเรียนต่อหรือสมัครงาน

**Persona 1 — "มิ้นท์" นักศึกษาปี 2 (ผู้ใช้หลัก):**
อายุ 19 ไม่เคยเรียนจีนเลย ต้องการ HSK 1 ยื่นสมัครโครงการแลกเปลี่ยน มีเวลาวันละ ~30 นาทีบนมือถือ (บางช่วงไม่มีเน็ต เช่น บนรถ) — ต้องการรู้ว่า "ตอนนี้พร้อมสอบหรือยัง" ไม่ใช่แค่นับคำที่ท่องแล้ว

**Persona 2 — "เบียร์" คนทำงาน (ผู้ใช้รอง):**
อายุ 27 เคยท่องศัพท์จากแอปทั่วไปแล้วเลิกกลางทาง เพราะรู้สึกฝึกซ้ำสิ่งที่ทำได้อยู่แล้วแต่จุดอ่อนจริง (แยกเสียง zh/ch/sh ไม่ออก) ไม่เคยถูกชี้ — ต้องการระบบที่บอกจุดอ่อนตรง ๆ แล้วเจาะฝึกให้

**ผู้ใช้แฝง:** ทีมผู้พัฒนา (หฤทัยเป็นผู้ตรวจเนื้อหา / ผู้ทดสอบจริงคือแหล่งข้อมูลเทรน pyBKT — ทุกการตอบ = 1 log, ขอ consent ตาม PDPA)

> หมายเหตุ: Persona "มิ้นท์"/"เบียร์" เป็นตัวละครสมมติที่แต่งขึ้นเพื่อสื่อสาร requirement — สร้างจากนิยามกลุ่มเป้าหมายใน proposal (คนไทยไม่มีพื้นฐาน เตรียม HSK 1–2)

## 4. ขอบเขต MVP: โมดูล 8 ตัว (ตาม proposal 1.5.1)

ครอบคลุมทักษะที่ข้อสอบ HSK 1–2 วัดจริงและตรวจเป็นปรนัยได้: **การฟัง + การอ่าน** (ข้อสอบมี pinyin กำกับ)

**กฎเหล็กการจัดลำดับ:** ทำแกน (โมดูล 1–4 + Mock Exam) ก่อน — ถ้าช้าตัดจากท้าย **ห้ามตัดแกน**
- **P0** = แกน (ไม่มี = โครงงานล้ม) · **P1** = สำคัญ (ทำให้เป็นแอปติวที่น่าเชื่อถือ) · **P2** = มีก็ดี

### โมดูล 1: คลังคำศัพท์ + บัตรคำ (Vocabulary & Flashcard) — P0

- **User story:** ผู้เรียนใหม่อยากเรียนศัพท์ HSK 1 ทีละคำ พร้อมพินอิน ความหมายไทย และเสียงอ่าน แม้ไม่มีเน็ต
- **Requirements:**
  - นำเข้าคำศัพท์จาก **HSK 3.0 word list เท่านั้น** (GitHub: `drkameleon/complete-hsk-vocabulary`, `ivankra/hsk30`) — HSK 1 = 300 คำ, HSK 2 = 500 คำ (สะสม) · ห้ามใช้ลิสต์ 2.0 เก่า
  - ความหมายไทย: เก็บ จีน + อังกฤษ (CC-CEDICT — ใส่เครดิต CC BY-SA) → AI แปลไทยทีเดียว (ไม่แปลทอดต่อทอด) → **หฤทัยตรวจก่อนเข้าใช้จริง**
  - เสียงอ่าน: edge-tts **pre-generate + cache** (ห้ามเรียกสดตอนผู้ใช้กด — ต้องออฟไลน์ได้)
  - แสดง stroke order ด้วย hanzi-writer (P2 ภายในโมดูล)
- **Acceptance criteria:**
  - [ ] คำ HSK 1 ครบ 300 คำ มีพินอิน + ความหมายไทย + ไฟล์เสียง ครบทุกคำ
  - [ ] คำแปลไทย 100% ผ่านการตรวจโดยหฤทัย
  - [ ] เปิดบัตรคำ + เล่นเสียงได้ในโหมด airplane (หลังโหลดครั้งแรก)

### โมดูล 2: แบบจำลองผู้เรียน — Learner Model (pyBKT) — P0

- **User story:** ผู้เรียนอยากรู้ว่าตัวเอง "แม่น" ทักษะไหนแค่ไหน (คำศัพท์/วรรณยุกต์/พยัญชนะ/ไวยากรณ์) ไม่ใช่แค่นับข้อถูก
- **Requirements:**
  - ทุกการตอบ = 1 log (`user / skill (KC) / ถูก-ผิด / เวลา`) → เก็บใน Supabase (ผ่าน Dexie ตอนออฟไลน์แล้ว sync)
  - **Q-matrix**: ตารางจับคู่ข้อสอบ↔ทักษะ (คำศัพท์ + ไวยากรณ์ 48/129 จุด + จุดผิด Thai-L1 เป็น Knowledge Component)
  - pyBKT **pre-train offline** ด้วยข้อมูลผู้เรียนไทยที่เก็บเอง → runtime (FastAPI) คำนวณแค่ posterior · **cold start** ใช้ค่าตั้งต้นจากงานวิจัย
  - วัดด้วย AUC (scikit-learn) + ablation มี/ไม่มี Thai-L1
- **Acceptance criteria:**
  - [ ] มี Q-matrix ตั้งต้นครอบคลุมข้อสอบทุกข้อใน item bank (ทุกข้อผูก KC อย่างน้อย 1 ตัว)
  - [ ] API คืนค่า mastery ต่อทักษะของผู้ใช้หนึ่งคนได้ (posterior อัปเดตหลังตอบแต่ละข้อ)
  - [ ] pipeline วัด AUC รันได้จริง (พิสูจน์ด้วย SLAM ก่อน แล้วรันซ้ำบนข้อมูลไทยเมื่อมี log พอ)

### โมดูล 3: วินิจฉัยจุดอ่อนเฉพาะคนไทย — Thai-L1 Diagnosis ⭐ — P0 (จุดขาย)

- **User story:** ผู้เรียนตอบผิดแล้วอยากรู้ว่า "ผิดเพราะอะไร" (เช่น สับสนวรรณยุกต์ 2/3 เพราะ contour ไม่ตรงกับไทย) และได้แบบฝึกเจาะจุดนั้นซ้ำ
- **Requirements:**
  - **Thai-L1 Error Catalog**: แต่ละรายการมี จุดผิด / ตัวอย่าง / สาเหตุ (transfer จากไทย) / ทักษะที่ผูก (KC ผ่าน Q-matrix) / วิธีเจาะสอน / หลักฐานงานวิจัยจริง (ห้ามแต่ง citation)
  - จุดผิดหลัก 3 กลุ่ม (มีงานวิจัยรองรับ): ① วรรณยุกต์เสียง 2/3 (Rungruang & Mu 2017) ② zh/ch/sh/r — ไทยไม่มี retroflex (Suphasa & Chi 2017) ③ ไวยากรณ์ถ่ายโอน/ลำดับคำขยาย (Chankrajang 2022: 补语 ผิด 48.07% ในข้อสอบคำเสริมกริยา ม.6, n=169)
  - **Distractor ของข้อสอบต้องสะท้อนจุดผิดคนไทย** → ตอบผิดข้อไหนบอกได้ว่าพลาดเพราะอะไร
  - เมื่อ mastery ของ KC จุดผิดต่ำ → ระบบจัดแบบฝึกเจาะจุดนั้นเข้าคิว
  - **ทุกรายการต้องผ่านการตรวจโดยหฤทัยก่อนเข้าเล่ม/item bank**
- **Acceptance criteria:**
  - [ ] Catalog ฉบับแรกครอบคลุม 3 กลุ่มหลัก ทุกรายการมีอ้างอิงงานวิจัยจริง + ผ่านหฤทัย
  - [ ] ตอบผิดข้อที่มี distractor Thai-L1 → ระบบ log ได้ว่า "พลาดจุดผิดข้อไหน" และแสดงคำอธิบายให้ผู้เรียน
  - [ ] มีเส้นทาง "เจาะฝึกซ้ำ" ที่ป้อนข้อจากจุดอ่อนที่วินิจฉัยได้
  - [ ] (evaluation) ablation แสดงผลต่าง AUC มี/ไม่มี KC Thai-L1

### โมดูล 4: ทบทวนเว้นช่วง — Spaced Repetition (FSRS) — P0

- **User story:** ผู้เรียนอยากทวนคำ "ตอนกำลังจะลืมพอดี" ไม่เสียเวลาทวนคำที่ยังจำได้แม่น และทวนได้แม้ออฟไลน์
- **Requirements:**
  - **FSRS v6**: ts-fsrs (client — ทวนออฟไลน์ได้) + py-fsrs (server) · ใช้ค่าตั้งต้นสำเร็จรูปของ FSRS ไม่ต้องเทรนเอง
  - ของที่จัดคิว = คำศัพท์ HSK 1–2 ในบัตรคำ · ผลทวน sync ขึ้น Supabase เมื่อออนไลน์
  - **แยกบทบาทชัด**: FSRS ตอบ "ทวนเมื่อไหร่" · pyBKT ตอบ "แม่นแค่ไหน" — ห้ามสับสนในเล่ม/แอป
- **Acceptance criteria:**
  - [ ] มีคิว "วันนี้ต้องทวน" ที่คำนวณจากสถานะ D/S/R ของแต่ละการ์ด
  - [ ] ทำรอบทวนจนจบได้ในโหมดออฟไลน์ แล้ว sync ขึ้น Supabase เมื่อกลับมาออนไลน์โดยข้อมูลไม่หาย
  - [ ] มี baseline (SM-2/ตารางคงที่) ให้เทียบ retention ตอน evaluation

### โมดูล 5: ฝึกการฟัง — Listening Practice — P1

- **User story:** ผู้เรียนอยากฝึกข้อฟังแบบ HSK จริง และรู้ว่าหูตัวเองแยกเสียงคู่ยาก (2/3, zh/ch/sh) ได้หรือยัง
- **Requirements:**
  - ข้อสอบฟังตามรูปแบบ HSK 1–2: ฟังแล้วเลือกภาพ / ถูก-ผิด / เลือกตอบ — เฉลยตายตัว ตรวจ rule
  - **minimal pair drill**: คู่วรรณยุกต์ 2 vs 3, คู่ zh/ch/sh — วินิจฉัย "หู" โดยไม่ต้อง ASR (แต่ละข้อผูก KC Thai-L1)
  - **ข้อฟังต้อง audio-only** — ห้ามโชว์พินอิน/ฮั่นจื้อของสิ่งที่ให้ฟังบนโจทย์ (บทเรียนจาก mockup อาจารย์: "ข้อฟังเฉลยตัวเอง")
  - เสียงจาก edge-tts pre-generate + cache (สำรอง: MeloTTS)
- **Acceptance criteria:**
  - [ ] ไม่มีข้อฟังข้อไหนแสดงข้อความที่เฉลยตัวเอง (ตรวจรีวิวทุกข้อ)

## 6. Non-Functional Requirements

### 6.1 ออฟไลน์ (Offline-first)
- แกนเรียน (บัตรคำ) + ทวน (FSRS ผ่าน ts-fsrs) + ข้อฝึกที่ cache แล้ว **ต้องทำงานได้โดยไม่มีเน็ต** หลังโหลดครั้งแรก
- กลไก: Serwist (Service Worker — เก็บตัวแอป/บทเรียน/เสียง pre-generate) + Dexie/IndexedDB (ข้อมูล + log ระหว่างออฟไลน์) → sync ขึ้น Supabase เมื่อออนไลน์
- **หลักการ: IndexedDB = ที่พัก · Supabase = ตัวจริง** — iOS อาจลบข้อมูลเว็บถ้าไม่เปิดแอป ~7 วัน → sync บ่อย ห้ามหวังพึ่ง IndexedDB เป็นที่เก็บถาวร (log = ของมีค่าที่สุด ใช้เทรนโมเดล ห้ามหาย)
- ⚠️ ห้ามใช้ next-pwa (เลิกพัฒนาแล้ว) — ใช้ Serwist

### 6.2 ประสิทธิภาพ
- โหลดหน้าแรก **< 3 วินาที** บนมือถือ (เครือข่าย 4G ทั่วไป)
- ตรวจคำตอบ + อัปเดต mastery รู้สึกทันที (posterior คำนวณเบา — โมเดล pre-train offline แล้ว)
- รับมือ cold start ของ backend ฟรี (ดู 6.3) ด้วย keep-alive / UX รอที่สุภาพ

### 6.3 ต้นทุน: ฟรี 100% ทุกชั้น + โควตา free tier ที่เกี่ยว

| ชั้น | บริการ | โควตา/เงื่อนไขที่ต้องรู้ (ยืนยัน 2026) |
|---|---|---|
| เว็บ | **Vercel / Cloudflare Pages** | deploy อัตโนมัติจาก GitHub |
| Backend ML | **Hugging Face Spaces** (Docker) | RAM 16GB (พอสำหรับ pyBKT+pandas) · **หลับหลัง 48 ชม.ไม่มีคนเรียก** (ข้อมูลไม่หาย ตื่นช้าครั้งแรก) → keep-alive ping ก่อนเดโม |
| DB + Auth | **Supabase** | DB 500MB · Auth 50k MAU · Storage 1GB (พอสำหรับไฟล์เสียง) · **pause หลัง 7 วันไม่มี query** → cron ping |
| TTS | **edge-tts** | ฟรี ไม่ต้อง key แต่ต้องเน็ต → pre-generate + cache เท่านั้น (สำรอง: MeloTTS) |
| LLM (เสริม) | **Gemini Flash** | ฟรี ~1,500 req/วัน · เรียกจาก server เท่านั้น |
| ❌ ห้ามใช้ | Render free (RAM 512MB ไม่พอ) · Fly.io / Railway / Koyeb (เลิกฟรีแล้ว) | |

### 6.4 ความปลอดภัย / PDPA
- **Consent ก่อนเก็บ log**: ข้อมูลการตอบใช้เทรนโมเดล → ต้องมีฟอร์มขอความยินยอมตาม PDPA ตั้งแต่แรกใช้งาน (ออกแบบตั้งแต่ sprint แรก)
- **Anonymize/pseudonymize**: dataset ที่ใช้วิเคราะห์/เผยแพร่ (เช่น Thai-L1 catalog เป็น open dataset) ต้องไม่ระบุตัวตนผู้เรียน
- **ห้าม API key ใน frontend** — key ทั้งหมดอยู่ใน env ฝั่ง server · ห้าม commit `.env` (มี `.gitignore` กันแล้ว)
- ใช้ Supabase Auth + Row Level Security — ผู้ใช้เห็นเฉพาะข้อมูลตัวเอง
- เครดิตไลเซนส์: CC-CEDICT (CC BY-SA) ต้องใส่เครดิตในแอป/เล่ม

### 6.5 อุปกรณ์เป้าหมาย
- **มือถือเป็นหลัก** (responsive, ติดตั้งเป็น PWA ได้ทั้ง Android/iOS) · เดสก์ท็อปใช้ได้
- รองรับข้อจำกัด iOS Safari (IndexedDB eviction ~7 วัน — ดู 6.1)
- UI ภาษาไทยทั้งหมด (กลุ่มเป้าหมายไม่มีพื้นฐานจีน)

## 7. User Flows หลัก 3 Flow

### Flow A: ผู้ใช้ใหม่ → Pre-test → เริ่มเรียน
```
สมัคร/ล็อกอิน (Supabase Auth)
 → ยอมรับ consent เก็บข้อมูล (PDPA) — บังคับก่อนเริ่ม
 → Pre-test: Mock Exam HSK 1 (ทำหน้าที่ placement + pre-score ของ pre/post)
    · ผู้ไม่มีพื้นฐานจริงคาดว่าคะแนนต่ำ — ระบบสื่อสารเชิงบวก "นี่คือจุดตั้งต้น"
 → ระบบตั้งค่า Learner Model: cold start จากค่าวิจัย + ปรับด้วยผล pre-test (ผ่าน Q-matrix)
 → Dashboard แนะนำจุดเริ่ม: ชุดคำศัพท์แรก + แบบฝึกตามจุดอ่อนที่เห็นจาก pre-test
```

### Flow B: วนเรียนรายวัน (core loop)
```
เปิดแอป (ออนไลน์หรือออฟไลน์)
 → 1) ทวนคิว FSRS วันนี้ (บัตรคำที่ "กำลังจะลืมพอดี") — ทำได้ออฟไลน์
 → 2) เรียน/ฝึกใหม่: บัตรคำชุดถัดไป + ข้อฝึกฟัง/อ่าน (รวม minimal pair)
 → 3) ทุกการตอบ → log (Dexie ถ้าออฟไลน์) → sync Supabase → pyBKT อัปเดต mastery
 → 4) ถ้า mastery ของ KC จุดผิด Thai-L1 ต่ำ → ระบบแทรก "เจาะฝึกซ้ำ" ตรงจุด + อธิบายว่าทำไมคนไทยพลาดตรงนี้
 → จบเซสชัน: Dashboard อัปเดตความคืบหน้า/streak
```

### Flow C: Mock Exam → ดูผล/ความพร้อมสอบ
```
เลือก Mock Exam (HSK 1 หรือ 2)
 → ทำข้อสอบ ฟัง+อ่าน เต็มชุด จับเวลาเหมือนสอบจริง (ทีละข้อ + progress bar + ย้อนแก้ได้ + คำตอบ persist)
 → ส่งข้อสอบ → ตรวจด้วย rule เทียบเฉลย → คะแนนสเกล 200 + ผ่าน/ไม่ผ่าน (เกณฑ์ 120)
 → รายงานผล: คะแนนรายทักษะ · จุดผิด Thai-L1 ที่เจอ · เทียบกับครั้งก่อน (gain)
 → ป้อน log เข้า pyBKT → Dashboard อัปเดต "ความพร้อมสอบโดยประมาณ"
 → แนะนำแผนต่อ: ทักษะที่ควรเจาะก่อนสอบจริง
```

## 10. คำถามที่ยังเปิดอยู่ (Open Questions)

1. ~~**ขนาด item bank ขั้นต่ำ**~~ — **มีข้อเสนอแล้ว 21 ส.ค. → ดู `กฎการทำงานระบบ-BUSINESS-RULES.md` ข้อ CG-08 (สถานะ 🔧 รอหฤทัยยืนยัน)**
   สรุปคำตอบ: **≥8 ข้อต่อ KC สำหรับข้อที่ต้องเขียนมือ · ≥3 คู่ต่อ KC สำหรับ minimal pair · ข้อคำศัพท์ปั้นสดไม่ต้องเขียน** — โดยมีเงื่อนไขว่า **ต้องลดจำนวน KC ที่ใช้ในการทดลองเหลือ ~23 ตัว** (Thai-L1 15 + คำศัพท์รายหมวด 5 + ทักษะ 3) ห้ามเอาไวยากรณ์ 48 จุดมาเป็น KC ในเฟสนี้
   หลักการที่ปลดล็อกคำถามนี้: **"โอกาสตอบ" ≠ "จำนวนข้อ"** — BKT ต้องการจำนวนการตอบต่อ KC ต่อคน (เกณฑ์ ≥8) ไม่ใช่จำนวนข้อที่แตกต่างกัน · เกณฑ์จริงจึงเป็นเกณฑ์โอกาสตอบ ซึ่งต้องเฝ้ารายวันด้วย query ⑤ ใน `query-ตรวจสอบข้อมูล.sql` ไม่ใช่นับข้อทีเดียวจบ
   *(ข้อ (ค) "ประกอบ Mock Exam หลายชุดไม่ซ้ำ" ตกไปแล้ว — PL-09 เคาะให้ใช้ชุดเดียว)*
2. **นิยาม "ความพร้อมสอบ" บน Dashboard** — ใช้สูตรไหน: คะแนน Mock ล่าสุดเทียบ 120/200 อย่างเดียว, ค่าเฉลี่ยถ่วงน้ำหนัก mastery ราย KC, หรือผสม? และสื่อสารเป็น % หรือระดับ (พร้อม/เกือบพร้อม/ยังไม่พร้อม)?
3. **โครงสร้าง section ของข้อสอบ 3.0 ฉบับจริง** — จำนวนข้อ/ประเภทข้อต่อ section หลัง 18 ก.ค. 2026 นิ่งหรือยัง? ต้องเช็ค chinesetest.cn อีกครั้งก่อน freeze รูปแบบ Mock Exam
4. **จำนวน log ขั้นต่ำก่อนสลับจาก cold start (ค่าวิจัย) ไปใช้พารามิเตอร์ที่เทรนจากข้อมูลไทยเอง** — ใช้เกณฑ์อะไรตัดสินว่าข้อมูลพอ?
5. **จำนวนผู้ทดสอบเป้าหมาย + ระยะเวลาใช้แอปขั้นต่ำ** สำหรับ pre/post ให้ gain score มีความหมาย (หลักสิบคน? ใช้กี่สัปดาห์?)
6. **แผนสำรองถ้า learner corpus (TOCFL/HSK/MIC) ขอเข้าถึงไม่ทัน** — ใช้เฉพาะงานวิจัย + ข้อมูลผู้ใช้เราเองพอไหมสำหรับ catalog ฉบับแรก? (ต้องเริ่มยื่นคำขอแต่เนิ่น ๆ)
7. **รายละเอียดฟอร์ม consent PDPA** — ข้อความ, ขอบเขตการใช้ข้อมูล (เทรนโมเดล + เผยแพร่ dataset แบบ anonymize), ถอนความยินยอมแล้วลบ log ย้อนหลังยังไง — ควรปรึกษาอาจารย์ที่ปรึกษา
8. **บัญชีไวยากรณ์ 48 จุด (HSK 1) ฉบับอ้างอิง** — ใช้แหล่งไหนเป็นทางการสำหรับตั้ง KC ไวยากรณ์ใน Q-matrix?
