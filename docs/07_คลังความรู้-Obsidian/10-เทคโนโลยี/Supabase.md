# Supabase

## คืออะไร
บริการฐานข้อมูล **PostgreSQL บนคลาวด์แบบฟรี** ที่แถม Auth (ระบบล็อกอิน) และ Storage (เก็บไฟล์) มาให้ในตัว — เป็น "ตัวจริง" ที่เก็บข้อมูลถาวรทั้งหมดของ星航

## Free tier ได้อะไรบ้าง
| ของ | โควตาฟรี | พอไหมสำหรับเรา |
|---|---|---|
| Database | 500MB | พอ — คำศัพท์ HSK 1–2 แค่ ~500 คำ + log การตอบเป็น text |
| Auth | 50,000 MAU | เหลือเฟือ (ผู้ทดสอบเราหลักสิบ-ร้อยคน) |
| Storage | 1GB | พอสำหรับไฟล์เสียงอ่านที่ pre-generate จาก edge-tts |

## ⚠️ กับดักที่ต้องจำ: หลับหลัง 7 วัน
โปรเจกต์ฟรีจะ**ถูกพัก(pause) ถ้าไม่มี query เลย 7 วัน** — ถ้าถึงวันเดโมแล้วฐานข้อมูลหลับ = หน้าแตกกลางห้องสอบ
→ ทางแก้: ตั้ง **cron ping** (ยิง query เบา ๆ อัตโนมัติเป็นระยะ) ก่อนช่วงเดโม/นำเสนอเสมอ

## ทำไมเลือก SQL (PostgreSQL) ไม่ใช่ NoSQL
1. **ข้อมูลเราสัมพันธ์กันหนัก** — ผู้เรียน ↔ คำศัพท์ ↔ ทักษะ (Q-matrix) ↔ จุดผิด Thai-L1 ↔ ข้อสอบ ต้อง join ข้ามตารางตลอด เช่น "คนนี้พลาดข้อไหน → ข้อนั้นทดสอบทักษะอะไร → ทักษะนั้นโยงจุดผิดคนไทยข้อไหน"
2. **log การตอบเป็น time-series** — ทุกการตอบ 1 ครั้ง = 1 แถว เรียงตามเวลา คือ dataset ที่ใช้เทรน [[pyBKT]] (ต้องขอ consent ตาม PDPA) — SQL query ดึงมาวัด AUC ได้ตรง ๆ ดู [[การวัดผลโครงงาน]]
3. ได้ Auth + Row Level Security มาในตัว ไม่ต้องเขียนระบบล็อกอินเอง

## IndexedDB = ที่พัก · Supabase = ตัวจริง
กติกาการเก็บข้อมูลของแอปเรา (design decision ใน HANDOFF ข้อ 6):
- ตอนออฟไลน์ → เก็บการตอบลง Dexie/IndexedDB ในเครื่องก่อน (ดู [[Next.js-PWA]])
- กลับมาออนไลน์ → sync ขึ้น Supabase ทันที
- เหตุผล: iOS อาจลบข้อมูลเว็บถ้าไม่เปิดแอป ~7 วัน + ข้อมูลการตอบคือของมีค่าที่สุดของโปรเจกต์ (ใช้เทรนโมเดล) — ห้ามให้หายเด็ดขาด
