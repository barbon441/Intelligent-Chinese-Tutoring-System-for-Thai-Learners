# FastAPI

## คืออะไร
เฟรมเวิร์กสร้าง backend (API server) ด้วย Python — เป็น "หลังบ้าน" ของ星航 ที่รับคำขอจากหน้าเว็บ [[Next.js-PWA]] แล้วส่งงานให้ตัวประมวลผล ML ทำ

## เปรียบเหมือนบริกรร้านอาหาร 🍜
- **ลูกค้า** = หน้าเว็บ Next.js ที่สั่งว่า "ขอข้อสอบชุดถัดไป" / "บันทึกคำตอบข้อนี้"
- **บริกร (FastAPI)** = รับออเดอร์ ตรวจว่าสั่งถูกรูปแบบไหม แล้วส่งเข้าครัว
- **ครัว** = [[pyBKT]] คำนวณความแม่น, [[FSRS]] จัดคิวทบทวน, jieba/pypinyin ประมวลภาษาจีน
- **async** = บริกรที่ไม่ยืนเฝ้าจานเดียวจนเสร็จ — ระหว่างรอครัว (เช่น รอ LLM ตอบ) ก็ไปรับออเดอร์โต๊ะอื่นต่อได้ → รองรับผู้ใช้หลายคนพร้อมกันโดยไม่ค้าง

## ทำไมเลือก FastAPI
1. **เป็น Python → รัน ML ในโปรเซสเดียว** — pyBKT, py-fsrs, jieba, pypinyin เป็นไลบรารี Python ทั้งหมด import มาใช้ตรง ๆ ไม่ต้องตั้งเซิร์ฟเวอร์แยกอีกตัว
2. **async ในตัว** — เหมาะกับงานที่ต้อง "รอ" เช่น เรียก Gemini Flash (LLM ส่วนเสริม — เรียกจาก server เท่านั้น key อยู่ใน env ห้ามฝังใน frontend)
3. **auto docs** — สร้างหน้าเอกสาร API (Swagger/OpenAPI) ให้อัตโนมัติ ทีม 2 คนไม่ต้องเสียเวลาเขียน spec เอง เปิด `/docs` แล้วกดทดสอบได้เลย
4. Engine แยกเป็นบริการ → อนาคตต่อช่องทางอื่นได้ (ตาม proposal)

## ตัวช่วยที่มากับมัน
| ตัว | หน้าที่ |
|---|---|
| Pydantic | ตรวจรูปแบบข้อมูลเข้า-ออกอัตโนมัติ (ส่งผิด type = โดนเด้งทันที) |
| Uvicorn | ตัวรันเซิร์ฟเวอร์จริง (ASGI) |

## ในโปรเจกต์เรา FastAPI ทำอะไรบ้าง
- รับ log การตอบจากหน้าเว็บ → เก็บลง [[Supabase]] → ป้อนเข้า [[pyBKT]] (คำนวณ posterior ตอน runtime — โมเดล pre-train แบบ offline)
- คำนวณตาราง [[FSRS]] ฝั่ง server (py-fsrs) คู่กับ ts-fsrs ฝั่ง client
- งาน NLP จีน: ตัดคำ (jieba) คุมระดับคำศัพท์ข้อสอบอ่าน, ใส่พินอิน (pypinyin) — ดู [[NLP-จีน-และเสียง]]
- deploy ฟรีบน Hugging Face Spaces (RAM 16GB แต่หลับหลัง 48 ชม. ไม่มีคนใช้) — ดู [[โฮสติ้งฟรี]]
