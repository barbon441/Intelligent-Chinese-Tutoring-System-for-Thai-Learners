# FSRS

## คืออะไร
FSRS = **Free Spaced Repetition Scheduler** — อัลกอริทึมโอเพนซอร์สจัดตาราง "ทบทวนแบบเว้นช่วง" (spaced repetition) ที่คำนวณว่าควรทวนการ์ดคำศัพท์ใบไหน *เมื่อไหร่* ให้มาทวนตอน "กำลังจะลืมพอดี" — เป็นเครื่องยนต์ของโมดูลทบทวนในจีนรู้ใจ

## หลักการ: โมเดล DSR + เส้นโค้งการลืม
ความจำคนเราเสื่อมตามเวลา (**forgetting curve** — เส้นโค้งการลืม) ทวนถี่ไปเสียเวลา ทวนช้าไปลืมแล้ว FSRS จำลองสถานะความจำของการ์ดแต่ละใบด้วย 3 ตัวแปร:

| ตัวแปร | ความหมาย |
|---|---|
| **D — Difficulty** | การ์ดนี้ยากแค่ไหนสำหรับคนนี้ |
| **S — Stability** | ความจำ "อยู่ทน" แค่ไหน (ยิ่งสูง ยิ่งลืมช้า) |
| **R — Retrievability** | ตอนนี้ยังนึกออกด้วยความน่าจะเป็นเท่าไหร่ |

ทุกครั้งที่ทวน ระบบอัปเดต D/S แล้วนัดวันทวนถัดไปให้ R ตกลงมาถึงเกณฑ์พอดี

## ต่างจาก SM-2 ยังไง
SM-2 (อัลกอริทึมคลาสสิกยุค SuperMemo ที่ Anki รุ่นเก่าใช้) เป็น**สูตรตายตัว** — คูณช่วงเวลาด้วย ease factor ไปเรื่อย ๆ ส่วน FSRS เป็น**โมเดลที่ fit จากข้อมูลการทวนจริง** จึงทำนายการลืมได้แม่นกว่าและปรับเข้ากับแต่ละคนได้ (ในโปรเจกต์เราใช้ SM-2/ตารางคงที่เป็น baseline ตอนประเมินผล — ดู [[การวัดผลโครงงาน]])

## จุดเด่นสำหรับโปรเจกต์เรา
- **มีค่าตั้งต้นสำเร็จรูป** ที่ fit มาจากข้อมูลการทวนจริงระดับหลายล้านรีวิว → **ไม่ต้องเทรนเอง** (ต่างจาก [[pyBKT]] ที่ต้องเทรนด้วยข้อมูลคนไทยเราเอง)
- **Anki รุ่นใหม่ใช้ FSRS ในตัว** → พูดกับกรรมการได้ว่า "เทคนิคเดียวกับ Anki"
- **มีงานวิจัยรองรับ**: SSP-MMC (KDD 2022) + โปรเจกต์ Open Spaced Repetition บน GitHub → เราอ้างงานวิจัยได้เลย ไม่ต้องพิสูจน์อัลกอริทึมซ้ำเอง (ดู [[งานวิจัยอ้างอิง]])

## ใช้ในโปรเจกต์ยังไง
- ใช้ **FSRS v6** ผ่านไลบรารี **ts-fsrs** (ฝั่ง client/[[Next.js-PWA]] — ให้ทวนได้แม้ออฟไลน์) + **py-fsrs** (ฝั่ง server/[[FastAPI]])
- ของที่ FSRS จัดคิวทวน = คำศัพท์ HSK 1–2 ในบัตรคำ (ดู [[HSK-3.0-ข้อเท็จจริง]])

## ⚠️ กฎเหล็ก: FSRS ≠ mastery
อย่าสับสนสองตัวนี้ในเล่ม/ตอนพรีเซนต์:
- **FSRS** ตอบว่า *"ควรทวนเมื่อไหร่"* (ความจำ)
- **[[pyBKT]]** ตอบว่า *"แม่นทักษะนี้แค่ไหน"* (mastery)
