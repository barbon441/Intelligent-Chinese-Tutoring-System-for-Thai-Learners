# บันทึกงาน 23 ก.ย. 2026

## 📼 วิเคราะห์นัดอาจารย์รอบ 6 (14 ก.ย. — คลิปเสียง14_09_69 บอลอัปโหลด 23 ก.ย.)

**ภาพรวม:** บอลเดิน ER ครบ 6 ก้าวด้วยตัวเอง อาจารย์**ไม่ติดโครง** (users / exam_forms / form_items / items / sessions / review_states ผ่านหมด) แต่ใช้วิธี "ถามหาตารางที่ตอบคำถามนี้ได้" แล้วเจอ**ช่องว่าง 3 จุดที่ผังยังไม่มีตารางรองรับ** + ยืนยันเพิ่มทักษะพูด + เสนอลดตารางที่ซ้ำซ้อน

### สิ่งที่ผ่าน (ไม่ต้องแก้)
- ก้าว ①–③ ทั้งหมด: อาจารย์ไล่ "ใครสอบ → เก็บที่ไหน → คะแนนอยู่ไหน" แล้วบอลชี้ users → sessions ได้ถูก · แกยอมรับว่า pre/post ใช้ชุดเดียวกันได้ "แต่ต้องคนละคะแนน" = sessions 2 แถว ✓
- review_states = "ตารางที่ผูก user กับคำ" — แกถามตรง ๆ บอลตอบถูก ✓
- โมเดล BKT: แกเข้าใจว่า "เราวัดเอง เพื่อบอกจุดอ่อนจุดแข็ง" ✓

|---|---|---|---|
| 1 | **เพิ่มทักษะพูด** | *"ขอเพิ่มเสียงเข้ามา จะได้อย่างน้อยครบสกิล — ถึงแม้ไม่มีสอบ ผมว่ามันจำเป็นอยู่ เผื่อเขาอยากพูดได้"* (ตะวัน: "ได้ค่ะ") | ✅ ยืนยันแล้ว (ตรง LINE) → เหลือทีมเคาะวิธีทำ ดู [[ทักษะพูด-วิเคราะห์ทางเลือก]] |

| 3 | **ตาราง user ↔ ประโยค** | *"นาย A เรียนประโยคที่ 1 ผ่านหรือไม่ผ่าน มีไหม? — รู้ทุกคำ แต่เรียงประโยคถูกตามที่ต้องการทุกอันหรือเปล่า มันอาจไปด้วยกันไม่ได้"* | 🔴 การบ้าน — ผังมีแค่ sentence↔word (สารบัญ) ไม่มี user↔sentence |

### วิเคราะห์ทีละข้อ + ข้อเสนอ

**ข้อ 2 — user ↔ content (จุดที่ตกหนักสุดของนัด)**
- หลักที่อาจารย์ใช้: **"สถานะที่ต้องไล่ดูได้ = ต้องเป็นตาราง · โค้ดคำนวณสดใช้ไม่ได้"** — ตอนนี้ "ผ่านหมวดไหน" อนุมานจาก sessions.kind=quiz + category + score ได้ แต่ไม่มีแถวที่บอกตรง ๆ ว่า "มิ้นท์ × หมวด 1 = สถานะอะไร"
- **เสนอ `category_progress`** (คน × หมวด): `user_id` · `category` · `started_at` · `words_learned` [cache จาก review_states] · `sentences_passed` [cache] · `quiz_best_score` [cache จาก sessions] · `quiz_passed_at` · `status` (not_started / learning / quiz_passed) — PK (user_id, category) · เป็นคู่แฝดของ `foundation_progress` (คน × ด่าน) แพตเทิร์นเดิม
- ส่วน content↔word และ content↔sentence ที่แกสเก็ตช์ — **มีอยู่แล้ว**ในรูป `words.category` / `sentences.category` (1 หมวดมีหลายคำ = 1:N ไม่ต้องตารางกลาง) → นัดหน้าต้องชี้ให้แกเห็น ไม่ใช่สร้างซ้ำ

**ข้อ 3 — user ↔ ประโยค**
- แกพูดถูก: sentence_words ตอบได้แค่ "เสิร์ฟได้ยัง" ไม่ได้ตอบ "เขาเรียงประโยคนี้ผ่านยัง" · ข้อมูลดิบมีใน attempts.sentence_id + is_correct แล้ว (บอลไม่ได้หยิบมาตอบ) แต่ตามหลักข้อ 2 ต้องมีสถานะรายประโยค
- **เสนอ `sentence_states`** (คน × ประโยค): `user_id` · `sentence_id` · `tries` · `best_correct` · `passed_at` — คู่แฝด review_states · โบนัส: FSRS นัดทวน*ประโยค*ได้ด้วยในอนาคต

**ข้อ 4 — นโยบาย post-test (PL-10 ❓)** ข้อเสนอให้เคาะ: pre 1 ครั้งตอนสมัคร (มีแล้ว PL-08) · **post 1 ครั้ง ปลดล็อกเมื่อ (ก) ผ่านควิซครบ 5 หมวด หรือ (ข) ถึงวันสุดท้ายของช่วงทดลอง (~วันที่ 10) แล้วแต่อะไรถึงก่อน** · สอบ post ซ้ำไม่ได้ (กัน practice effect — PL-09) · อยากซ้อมสนาม = mock คนละชุด ทำได้ไม่จำกัด · ข้อ (ข) จำเป็นเพราะกลุ่มทดลอง 10 วันอาจไม่มีใครเรียนครบ 5 หมวด → ไม่มี post = ไม่มี gain score

**ข้อ 5 — ลดตาราง**
- **mastery_snapshots ไม่ใช่ summary** — เป็นผลคำนวณของโมเดล (posterior BKT) ที่ SQL aggregate จากตารางหลักไม่ได้ + ต้องเก็บประวัติรายวันเพื่อพล็อตพัฒนาการ → **ควรคงไว้ แต่ต้องชี้แจงแกให้ชัดนัดหน้า** (บอลไม่ได้แย้งในห้อง) · สิ่งที่รับได้ตามหลักแก: คอลัมน์ [cache] ใน sessions/categories ให้ทบทวนว่าจำเป็นไหม
- **recommendations** — แยก 3 ชิ้นที่แกพูดรวมกัน: (1) *คำอธิบายจุดผิด* = thai_l1_catalog เป็นข้อเท็จจริงจากงานวิจัย เขียนครั้งเดียวใช้กับทุกคน **คงไว้แน่นอน** (นี่คือ contribution) · (2) *ข้อความแนะนำรายบุคคล* = เห็นด้วยกับแก: ให้ Gemini เขียนจากตัวเลข SWOT บน dashboard ไม่ต้องเก็บ — **ไม่ขัดกติกา "ไม่ใช้ LLM ตรวจ"** เพราะไม่ได้ตรวจคำตอบ แค่แต่งข้อความจากตัวเลข (Gemini Flash อยู่ใน stack แล้ว key ฝั่ง server) · (3) *ตาราง recommendations* = log ว่าระบบชี้ KC ไหน + ทำตามไหม → มี 2 ทาง: ตัดตามอาจารย์ (เสียหลักฐาน "การวินิจฉัยเปลี่ยนพฤติกรรม" ในเล่ม) หรือคงแบบบาง (4 ช่อง ไม่มีข้อความ) — **รอบอล/ตะวันเคาะ** · ข้อเสนอ: คงแบบบาง + ชี้แจงแกว่า "ไม่ได้เก็บคำแนะนำ เก็บแค่ว่าชี้ KC ไหนแล้วเขากดทำไหม"
- เกณฑ์จุดแข็ง/จุดอ่อนที่แกเสนอ (≥50% = แข็ง) → ตรงกับ BK-04 threshold ที่ยังไม่เคาะ — ใช้ p_mastery ≥ 0.5 เป็นค่าตั้งต้นได้

### สิ่งที่บอลทำได้ดี / จุดสะดุด
- ✅ เดินครบ 6 ก้าวเป็นครั้งแรกหน้าอาจารย์ · ตอบ sessions / review_states / pre=post ถูก · ตอบ "รอบเดียว" ชัดเจน
- ⚠️ พอแกถาม "ตารางไหนบอกว่าใครเรียน content ไหน" ตอบว่า *"น่าจะเป็นโค้ดที่เขียน"* → แกไม่รับทันที — **บทเรียนหลักของนัด: อะไรที่ต้อง "ไล่ดูย้อนหลัง" ได้ ต้องอยู่ในตาราง**
