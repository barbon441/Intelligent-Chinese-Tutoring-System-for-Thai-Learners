### สองข้อที่เป็น "เพิ่มใหม่" ไม่ใช่แค่แก้คำ
1. **ขาดเทคโนโลยี** — อาจารย์: *"ขาดส่วนของพวกเทคโนโลยี ภาษาหรือเทคนิคที่เราจะเอามาใช้... รวมถึง[ฐาน]ข้อมูลด้วย... หน้าบ้านใช้อะไรบ้าง"* → ต้องใส่ Next.js/TypeScript · FastAPI/Python · PostgreSQL บน Supabase · **BKT** · **FSRS**
2. **ขาดผลลัพธ์สุดท้าย** — อาจารย์: *"อย่าลืมว่าผลสุดท้ายของระบบของเราจะใช้เป็นอะไร"* → ปิดท้ายด้วยผลที่คาดว่าจะได้รับ + วิธีประเมิน (เทียบคะแนน mock ก่อน/หลัง รายงานเป็น**แนวโน้ม** ไม่เคลมว่าสอบผ่าน)

### ⚠️ บทเรียน: ตอบ "ยังไม่มี AI ครับ" สั้นไป
อาจารย์ถาม *"มี AI มั้ย"* เราตอบว่ายังไม่มี — แต่จริง ๆ โครงงานมีแบบจำลอง 2 ตัวคือ **pyBKT** (ความแม่นรายทักษะ) กับ **FSRS** (กำหนดการทบทวน) ซึ่งเป็นจุดต่างทางวิชาการของเราเอง
ครั้งหน้าถ้าถามแบบนี้ให้ตอบว่า "ไม่มี LLM/การวิเคราะห์เสียง แต่ใช้ BKT กับ FSRS เป็นแกน"
ส่วน ASR/วิเคราะห์เสียง = future work → ระบุใน "ขอบเขต" ของตัวบทความ ไม่ต้องยัดในบทคัดย่อ

### แก้คำอื่น ๆ
- หัวกระดาษ: เติม **"ดร."** ให้ ผศ.ดร.สมนึก สินธุปวน (ผู้นิพนธ์ประสานงาน)
- เปิดบทคัดย่อ: "โครงงานนี้**มีวัตถุประสงค์เพื่อพัฒนา**..." · วัตถุประสงค์ใช้ **1) 2) 3)** ไม่ใช่ "หนึ่ง สอง สาม"
- เลิกใช้ **"เอชเอสเค"** → **"การสอบวัดระดับความรู้ภาษาจีน (HSK)"** ทั้งบทคัดย่อและคำสำคัญ
- คำสำคัญเพิ่ม **"ผู้เรียนชาวไทย"** ให้ตรงชื่อเรื่อง
- ชื่อบทความ + ลำดับผู้แต่ง อาจารย์ผ่านแล้ว ไม่ต้องแก้

## 🇹🇭 กฎใหม่จากบอล: บทคัดย่อไทย = ไทยล้วน

ร่างแรกผมใส่ชื่อเทคโนโลยีเป็นอังกฤษ (Next.js, FastAPI, PostgreSQL, BKT, FSRS, (HSK)) → **บอลตีกลับ**
กฎคือ **บทคัดย่อภาษาไทยห้ามมีอักษรโรมันแม้แต่ตัวเดียว** ศัพท์ไหนไม่มีคำแปลไทยให้ทับศัพท์

ลำดับการเลือกคำ: **มีคำแปลไทย → ใช้คำแปล** · **ไม่มี → ทับศัพท์เป็นอักษรไทย**

| อังกฤษ | ไทย |
|--------|-----|
| HSK | การสอบวัดระดับความรู้ภาษาจีน (เอชเอสเค) ← ของเดิมถูกแล้ว ไม่ต้องแก้ |
| front end / back end | ส่วนติดต่อผู้ใช้ / ส่วนประมวลผลฝั่งเซิร์ฟเวอร์ |
| Next.js · TypeScript · IndexedDB | เน็กซ์ดอตเจเอส · ไทป์สคริปต์ · อินเด็กซ์ดีบี |
| FastAPI · Python | ฟาสต์เอพีไอ · ไพทอน |
| PostgreSQL · Supabase | โพสต์เกรสเอสคิวแอล · ซูปาเบส |
| BKT · FSRS | การติดตามความรู้เชิงเบส์ · อัลกอริทึมกำหนดการทบทวนแบบเว้นช่วง |
| Progressive Web App · LLM | เว็บแอปพลิเคชันแบบโปรเกรสซีฟ · แบบจำลองภาษาขนาดใหญ่ |

ตารางเต็มอยู่ใน `docs/01_เอกสารโครงงาน/บทคัดย่อ-CSTI-MJU8.md` §B — **ทั้งทีมใช้คำเดียวกันทั้งเล่ม**
ชื่อเต็มภาษาอังกฤษไปเขียนในหัวข้อ "เครื่องมือและวิธีการดำเนินงาน" ของตัวบทความแทน (ตรงนั้นปนอังกฤษได้)

## ❌ จุดที่ผมตีความผิด แล้วบอลตีกลับ (บันทึกไว้กันพลาดซ้ำ)

ผมอ่านคลิปท่อน HSK แล้วสรุปว่า **ต้องแก้ทั้งตัวบทคัดย่อและคำสำคัญ** → **ผิด**
บอลอยู่ในห้องตอนนั้น ยืนยันว่าอาจารย์หมายถึง **บรรทัดคำสำคัญเท่านั้น** เพราะเดิมคำสำคัญมีแค่ `เอชเอสเค` ลอยเดี่ยวโดยไม่มีคำเต็ม
ส่วนตัวบทคัดย่อเขียน "การสอบวัดระดับความรู้ภาษาจีน (เอชเอสเค)" ถูกต้องอยู่แล้วตั้งแต่แรก — **ไม่ต้องแตะ**

**บทเรียน:** คลิปถอดเสียงตรงนี้กำกวมจริง (ผมเองก็ mark ไว้ว่าไม่ชัด) — คราวหน้าที่เจอท่อนกำกวม **ถามบอล/ตะวันก่อน อย่าเดาแล้วลงมือแก้** เพราะคนที่อยู่ในห้องจำได้แม่นกว่าเสียงที่ถอดมา

### ค้างรอเคาะ
- สะกดชื่อกรรมการท่านที่ 4: หน้าที่ส่งเขียน "ปวิณ เชื่อนแก้ว" แต่อังกฤษ "Paween Khoenkaw" → น่าจะเป็น **"ปวีณ เขื่อนแก้ว"** — ต้องยืนยันก่อนแก้
- ~~ท่อนคลิปที่เสียงกำกวมเรื่อง HSK~~ ✅ ปิดจบด้วยกฎไทยล้วน (ดูหัวข้อข้างบน)
- ศัพท์จีน/ชื่อทักษะในบทคัดย่อ ("เสียงม้วนลิ้น", "วรรณยุกต์เสียงที่ 2 กับเสียงที่ 3") → ตะวันตรวจ

## 📼 วิเคราะห์นัดอาจารย์ที่ปรึกษารอบ 5 (คลิปเสียง5 — โชว์ ER 23 ตาราง · บอลอัปโหลด 24 ส.ค.)

### สิ่งที่ทำได้ดี
- โซนเนื้อหาบอลเล่าเองได้ตลอด: หมวด → คำ → ประโยค และอธิบาย **sentence_words ได้ครบถ้วนที่สุดในคลิป** (position · เทียบตารางทบทวน · กติกาสร้างประโยคจากคำที่เรียนแล้วเท่านั้น) — ตรงกับที่ซ้อมมาเป๊ะ
- อาจารย์เห็นด้วยกับจังหวะ: *"ที่ผมอยากดู database ตอนนี้เพราะเดี๋ยวพอทำไปเสร็จมันจะเริ่มเยอะ... ตอนนี้ยังถอยหลังทัน"*

### จุดสะดุด + คำสั่งชัดจากอาจารย์
- โซนข้อสอบ (items / exam_forms / sessions — ส่วนที่ตะวันเพิ่ม 21 ส.ค.) บอลตอบไม่ได้ และยอมรับตรง ๆ ว่ายังไม่ได้ไล่ดู · อาจารย์: **"ไม่ได้สิ ต้องไปด้วยกันทั้งคู่"** — ทั้งสองคนต้องอธิบายได้ทั้งผัง
- ผังเต็มเส้นก่ายกันดูยาก → **ให้ทำฉบับย่อ: หัวตาราง + คีย์ (PK/FK) เท่านั้น** ไว้ใช้อธิบาย/ตอนสอบ
- วิธีทำความเข้าใจที่อาจารย์สอน: **ไล่ตามกระบวนการผู้ใช้** (user → ทดสอบ → เชื่อม category → ผลอยู่ตารางไหน) ไม่ใช่ท่องทีละตาราง — ตรงกับไฟล์ [[ความต้องการข้อมูล-User-Journey]] ของตะวันพอดี ใช้เป็นสคริปต์ซ้อมได้เลย
- คำถามออกแบบที่อาจารย์โยน (ข้อสอบ↔คลังข้อสอบ↔คำ/ประโยค · pre/post ต้องเชื่อมคลังชุดเดียวกัน · ตารางเรียน vs สอบ · ตารางกลาง user↔category) — **ดีไซน์ปัจจุบันตอบได้เกือบหมดแล้ว** (form_items · sessions.kind+category · attempts.word_id/sentence_id) → การบ้านจริงคือ "เล่าให้ได้" ไม่ใช่แก้ schema

### การบ้านใหม่ 3 ประเด็น "เชิงภาษาศาสตร์" (ต้องเขียนลง paper)
1. ตรวจการเรียงประโยคยังไง — อัลกอริทึมอะไร map ระหว่างคำตอบผู้เรียนกับเฉลย (คำตอบเรา: เทียบลำดับเฉลยจาก sentence_words.position แบบ rule-based)
2. จุดยืนเรื่องตรวจเสียงพูด — ทีมตอบว่า HSK1-2 ไม่สอบพูดจึงตัด · อาจารย์ทิ้งท้าย *"ซาวด์ที่ผมให้ไปไม่ได้ใช้เลยใช่มั้ย"* → ⚠️ ไปดูของที่อาจารย์เคยส่งให้ว่าคืออะไร แล้วเขียนเหตุผลการตัดใน "ขอบเขต" ให้แน่น
3. การตรวจความถูกต้องใช้ API ไหม — เราตรวจด้วย rule ของเราเอง ต้องอธิบายชัด

### ข้อมูลใหม่เรื่องเส้นทางส่งงาน (ปิดคำถามค้าง "สอบ 50%/100%" ได้ครึ่งหนึ่ง — รู้รูปแบบ ยังไม่รู้วันที่)
- **สอบ 50%** = ช่วง midterm เวียนนำเสนออาจารย์แต่ละท่าน · **100%** = ทำโปสเตอร์เสนอกรรมการในนิทรรศการหลักสูตร
- จากนั้น **paper ส่ง CSTI** + ขึ้นนำเสนองานประชุมวิชาการ 1 ครั้ง
- อาจารย์ส่ง **template paper ของรุ่นพี่** มาให้ → การบ้าน: อ่าน + เอาโปรเจกต์+template ให้ AI ช่วยร่าง paper แล้วอ่านตรวจ มาคุยกัน · ลำดับที่แนะ: **ทำ paper ก่อน → ค่อย gen poster จาก paper**
- นัดหน้า: เว้น 1 อาทิตย์ (ตะวันติดสอบพฤหัส)
